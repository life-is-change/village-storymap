# 场景方案接入村庄模拟

主平台仍从根目录 `index.html` 打开。进入当前村庄的小组空间，打开场景设计工作室，点击顶部 **村庄模拟**。顶部 **虚拟村庄 ↗** 或模拟面板的 **虚拟村庄 · 完整体验 ↗** 可打开完整虚构村庄，独立地址为 `/village_game/`。

## 使用顺序

1. 场景设计左侧按“设定范围 → 规划道路 → 放置组件”操作。设定范围创建一处公园、广场等活动场地，使用贴地填充与轮廓，不自动铺装或生成建筑；规划道路用于连接建筑、场地与现状路网。放置组件后，按完整几何包含关系在左侧显示“活动场地 → 内部组件”，重叠时归属面积最小的场地；跨边界组件显示在未归属清单。素材库仅供组件选择，包含铺装、场内小径、围护、绿化和家具；新画的组件小径不自动进入模拟路网。线和面点选节点后点“完成绘制”，完成后回到选择；“放弃本次绘制”仅清除草稿。组件可连续放置，点“结束放置”保留已放对象。绘制被拒绝时保留预览并解释原因。
2. 打开村庄模拟，左侧按“模拟范围 → 路网与出入口 → 设施功能 → 人群情境 → 检查与运行”操作。先绘制整片模拟范围，或采用当前村庄边界。紫色模拟边界独立保存在 `metadata.simulation.area`，不覆盖蓝色公园及其他设施边界。旧方案用途和道路配置保留，但在工作区再次启动前需要补划模拟范围。
3. 核对已选道路。道路仅在模拟范围内的部分参与，和范围边界相交的位置自动成为对外口，可切换为一个手动对外口。并非人物可以从任意边界穿出，仍须沿路进出；多口不会把两片断路虚接。设施入口继续按最近道路建议，允许人工修改；短接驳不能穿建筑、水体或越过模拟范围。缺少巷道时返回设计补画，再主动加入新路。
4. 进入“设施功能”，点击原三维建筑、场地或右侧对象列表，在底部按居住、经营、照护、公共文化、旅游分类选择图标与模型卡片；右侧设置容量、吸引力、人员和营业时间。此处给现有对象赋功能，不直接生成新房屋；未定义对象保留背景。范围外或跨边界设施的配置不会删除，但不参加本次模拟，检查报告会提示；完整纳入后才生效。
5. 面域设施可纳入内部长椅、树木、凉亭等作为配套。一个组件只归属一处设施，不能同时独立设为设施；类型多样性最多提供10点教学吸引力加成。
6. “人群情境”默认使用合成家庭及成年、老年、儿童的男女画像，结合现有设施分配岗位，不要求逐个人设定。设置常住人数、潜在客源、日期、周期和随机种子，或按范围内住宅容量建议人数。合成情境不代表调查事实；家庭是否住得下仍需检查。
7. 点击“检查并进入运行”，再“保存并开始模拟”。保存阶段明确显示等待，失败或25秒未返回则不启动并恢复操作，本机草稿保留；晚到的保存响应不能启动旧运行。真实服务器504仍需排查网络/服务，界面不会假报已保存。可暂停、调速、查看人物；完成周期后结果随方案保存，重新打开可恢复，最多保留5次摘要。

## 保存与比较

配置位于场景文档 `metadata.simulation`。通过现有场景服务保存；阿里云部署使用现有阿里云场景API、用户身份、空间权限和乐观版本控制，不新增数据库表，不调用4090，不在浏览器放数据库密钥。离线/版本冲突不显示为保存成功；发生冲突需返回设计处理，未保存成功时不会开始新运行。

每次运行冻结输入，记录源项目、村庄、空间、基线、方案revision、规则版本和SHA-256输入摘要。人口、潜在客源、种子、日历、模拟范围、基线、村庄和规则版本均相同的结果才显示同条件比较。摘要用于复现与区分输入，不是服务端防作弊签名；模拟当前由浏览器计算。

## 首版边界

- 常住人口最多180、日潜在来访最多80、周期最多7天、功能设施最多240、真实方案选中道路最多800线段（独立虚构体验仍为180）、功能设施与道路跨度最多2公里。超限停止并提示，不自动裁切路网。村庄其余区域仍保留底图显示。
- 同层路径交叉连通；桥梁、立交、跨水道路的通行语义需要人工检查。首版不从三维模型自动识别门和可走地面，也未模拟车流、道路拥挤容量或建筑内部行走。
- 保留面域真实外边界及面积用于设施归属、入口和连接阻挡；室外活动目前集中在入口附近。未定义用途的建筑不产生设施供给，但在实验范围内仍阻挡入口捷径。地形采用Cesium地面贴附，缺少地形数据时使用当前地球表面，未做室内/台阶级导航。

## 数据准备

工作室首次从三维视图打开时，也会构建当前空间经过修改、删除和版本解析的二维现状源，供建筑碰撞检查和模拟使用。不能直接用静态图层缓存代替当前空间现状。源对象优先使用图层与数据ID组合标识，缺少数据ID时使用业务编码；不能把道路名称当作唯一ID。已有配置的旧编号在可唯一匹配时兼容到新编号，打开面板不因此自动写库。无法匹配的旧配置保留并提示，需重新选择对象并明确移除失效配置。整体设计范围使用独立的 `boundary:selection` 引用，边界变化后下一次运行采用新几何，删除后会明确提示源设施已移除。当前模拟规则版本为 `platform-village-4`，不会把旧规则运行摘要当作同条件结果比较。

## 首次试跑与道路说明

建议先定义2处住宅和1处公园，人口6、潜在客源6/日、周期1天；沿用现状道路，在道路上设置一个村口，再检查、保存、运行。这是便于验证操作的小情境，缺少学校、生产和餐饮等设施会在结果中反映，不代表完整村庄已经具备这些服务。

设施未连通时，先点“检查方案”，展开“入口与道路连接”。每处设施会说明距离过远、障碍阻挡、所在道路未通村口或没有可选道路，并可“定位入口”“调整入口”。绿点和绿线表示可用的入口及短接驳；红点和红色虚线仅表示失败候选，不提供通行。自动短接驳上限为26米，且不能穿过建筑或水体；这只是教学参数，不代表现实中已经有路。

缺少巷道时，点击场景设计左侧“规划道路”，或模拟中的“返回设计补画巷道／步道”。依次点选中心线，点击“完成绘制”；也支持三维右键、二维双击完成。新路径进入当前方案的“村庄道路与步道”图层，可以超出公园范围，但必须在已知村界内；缺少村界时仍限制在旧版放置范围。首尾距现状道路或已有连接道路中心线不超过2米时自动吸附，中间节点保持原位。道路宽度及编辑方式见下文。移动场地范围不会暗中移动内部组件，归属随几何关系重新计算。

道路编辑现支持直接在三维进行：选中蓝色道路后点“编辑顶点”，拖黄色编号点，点蓝色中点插入节点；选顶点后可删除，至少保留两个。点“整体移动”可拖动整条道路。右侧“宽度（m）”修改实际米宽，选中高亮不改变宽度。每次松开鼠标经过村界、锁定和吸附规则检查后记录一个可撤销操作；取消未释放的拖动不提交，越界或锁定则恢复。二维仍使用原道路矢量的Modify/Translate操作，显示实际宽度、选中中心线和节点；改宽度、撤销后可继续编辑。切到二维或开始二维道路编辑时定位所选道路。场地与旧蓝框的三维平移/节点编辑仍通过二维完成。各视图修改同一份当前场景方案，不修改共享现状道路。

旧方案的蓝色 `selectionBoundary` 单独保留在“旧版放置范围”，不自动迁移成活动场地，以免改变既有模拟引用。可在地图选取或展开旧范围后点“选择旧蓝框”，再清除、平移、旋转或改节点。清除不删除已有场地或组件，可以撤销；也不会强制重新画框。后续组件能否独立场地放置尚未收紧限制，原有范围内组件与未归属组件保留。旧场景中未标注用途的 path 继续兼容为连接道路，不追溯更改已有方案。

补画后重新打开模拟，明确点击“加入未选设计步道”，再“检查方案”。单纯保存或打开面板不会自动把新路加入试验。应沿实际可走的巷道画到设施门前，确保这段小路与通往村口的主路相连；若门口方向不对，再使用“调整入口”。新增路径只属于当前场景方案，不修改其他小组或共享现状道路。

当前模拟读取当前空间的有效道路，也支持场景路径对象；未实现“场景内任意修改现状道路后自动写回对应2D空间”的完整双向编辑。现有场景方案以小组和管理员试用隔离，学生个人场景方案还未完整接入。后续道路功能必须通过当前空间对应的规划/个人版本接口保存中心线、宽度和节点，复用锁与版本控制，不能直接改共享基线。详见 `docs/superpowers/specs/2026-10-24-simulation-startup-design.md`。
- 人物岗位按当前服务岗位和农田供给生成；详细年龄、真实家庭和岗位调查导入尚未实现。个体行程和交流沿用生活模拟核心，不能当作现实客流预测。
- 结果保存运行摘要，未保存逐帧轨迹或跨轮设施成长存档。设施容量由显式配置控制，不再被示例白模尺寸限制；需由教师根据调查校准。

发布时使用更新后的 `linux/scripts/stage-web.py`，它会包含游戏和接入模块，并排除测试、研究目录、后端及凭据。发布镜像需要按新提交重新构建和验收；仅推送GitHub不会自动更新既有阿里云容器。
