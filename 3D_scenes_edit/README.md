# 3D 场景编辑模块

本目录是模块二“公共空间设计工作室”的独立业务边界。平台入口仍是仓库根目录的 `index.html`；`app.js` 和 `app-3d.js` 只提供当前课程、小组、空间、地图和 Cesium 视图桥接。

## 数据原则

- `SceneDocument` 是二维与三维共同使用的唯一场景文档。
- 永久保存的 GeoJSON 坐标使用 EPSG:4326。
- 高度、宽度、距离和占地尺寸统一使用米，角度统一使用度。
- OpenLayers 和 Cesium 只能在各自适配器渲染时转换坐标。
- 现状与小组基线永久只读；方案文档只保存基线引用和本组差异对象。
- 水平位置、绕竖轴旋转与水平缩放会影响二维占地；高度、俯仰、横滚和材质保存在三维扩展属性中，不改写二维几何。

## 目录职责

- `domain/`：场景文档、命令和几何规则，不依赖浏览器渲染引擎。
- `map_2d/`：OpenLayers 图层与交互适配器。
- `preview_3d/`：把同一场景文档渲染到 Cesium，并管理组件选中与放置预览。
- `interaction_3d/`：Cesium 地面选点、公共空间边界、组件放置和水平拖动。
- `assets/`：平台基础素材元数据、上传校验和组合组件。
- `persistence/`：Supabase、自动保存和本地恢复。
- `ui/`：学生工作台的 DOM 视图。
- `integration/`：把平台用户、小组、空间、OpenLayers 与 Cesium 转换为窄接口。
- `acceptance/`：完整工作流、性能预算和浏览器验收清单。
- `legacy/`：只读历史参考，不进入生产加载链。

## 部署前提

全新数据库先执行 `supabase_SQL/Scene Edit Studio.sql`。已经执行过旧版脚本的数据库，只需再执行一次 `supabase_SQL/MIGRATION - Scene Edit Admin Sandbox.sql`，它会保留现有小组数据并增加管理员个人沙盒。

## 使用路径

1. 在左侧课程任务中打开“方案设计与迭代”，点击“开始场景设计”。
2. 工作台直接进入现有 Cesium 三维村庄；管理员无需加入小组，学生仍使用所属小组方案。
3. 首次使用时在三维场景点击“划定范围”，依次选点并右键完成公共空间边界。
4. 从画布下方的组件栏选择座椅、树木、花坛等素材，在地面移动预览并单击放置；选择“移动”后可按住组件拖动。
5. 用“2D 校核”查看同一场景文档的俯视结果，并可继续绘制铺装、路径或精调节点；切回“3D 设计”继续空间体验。

管理员上传的 GLB 保存在个人素材范围，小组上传的 GLB 保存在对应小组范围，两者都不会修改共享现状空间。
