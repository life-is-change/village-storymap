# 公共空间3D设计卡顿修复

## 证据与原因

用户Chrome实际页面，管理员试用方案R38、8个对象、191栋白模、14条道路、6个原生小模型（48–132三角面/个）。Intel核显硬件加速；静止2s零重绘。没有把截图中的Ion超时、pgw404直接当作帧率根因。

前台轻微相机转动实测约6fps。相机changed事件中的scene-preview-adapter驻留计算同步重复查询固定点globe.getHeight；Cesium原生Model的RELATIVE_TO_GROUND也在更新和贴地回调中重复查同一点。约1.7s采样250次查询耗时1.59s。临时全局缓存对照1.8s渲染118帧，此包装随后恢复，未作为产品实现。

产品修复：每个记录按经纬度、terrainProvider对象及瓦片版本缓存高度；相机变化只计算屏幕可见性。原生Model采用NONE高度参考，把地面高+用户高偏移+素材校准偏移显式合入矩阵。地形瓦片加载结束、服务更换或坐标移动会刷新矩阵；异步GLB加载完成再校正一次地面高度。没有关地形、删模型、降分辨率或改方案。

## 实际浏览器验证

当前用户标签页临时加载修复版，并重开同一R38方案；UI仍显示“未修改”，没有保存或改对象。第一轮约41–44fps。进一步固定同一相机初始位置与同一750×517绘制缓冲进行旧/新对照：旧版2.478s渲染9帧（约3.6fps），新版2.050s渲染63帧（约30.7fps）。在线瓦片状态会影响具体帧率，这不是所有设备性能保证。

临时函数入口、性能采样包装、数据源显隐和测试相机变化均已恢复。当前预览实例使用修复版直至退出/刷新，服务器文件仍是旧版；正式更新需执行下述云端补丁。对照截图保存在E:/codex-tests/scene-terrain-performance-20261027/verified-r38.png。
