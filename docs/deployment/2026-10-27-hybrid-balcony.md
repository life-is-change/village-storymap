# 混合阳台补丁

## 规则与范围

有凹阳台证据且有对应通行门时，默认内凹1.0m，玻璃外表面至栏杆内侧净深1.5m。金属栏杆实际内侧外挑0.5225m（中心线0.5485m），楼板前缘0.6245m；截面厚度另算。石材、实体栏板按各自截面计算。不是实际测量，也不强制所有栏杆后窗改为凹阳台。

只对本层阳台局部覆盖，原贯通门廊和底层几何保持。已有大于1m的凹廊不强制缩浅，保留旧处理；旧JSON没有关系版本也不套新深度。原白模底层主体尺寸、位置和朝向不变，上层楼板与栏杆可超出原垂直外轮廓。实际不可见结构仍为规则补全。

楼板覆盖外挑和内凹区域，左右栏杆接到凹墙侧边；侧墙按合并后的凹进轮廓生成，避免重叠回墙。manifest新增balcony_dimensions与balcony_floor_support_samples，记录坐标、净深与真实楼板射线支承检查结果。

## 验证

同641×641原图和现有检测缓存（无新DINO调用、无付费API）经Blender3.6.23生成2个混合阳台，净深均1.5m、内凹1m；连续地板共10点支承检查，屋顶闭合与支承、门窗墙体穿透检查通过。独立部署合成场景生成1个混合阳台，5点支承检查通过，优化GLB309204字节。

代码复核发现并修复了整层门廊被上层阳台加深的问题；新增保持底层及更深原门廊的回归测试。真实GLB使用网页预览器加载，在1440/1280/390px检查通过。测试不代表远程重新识别后的效果已经验收。

最终回归608项Python测试通过、17项环境测试跳过。原图模型优化后400972字节（约0.38MiB），两个阳台10点楼板支承通过；独立代码复核确认无遗留重要问题。

本地结果位于E:/codex-tests/hybrid-balcony-20261027，含config.json、GLB、PNG、Blender场景、日志和manifest。当前生产quality版两端已由用户回传成功，本混合阳台补丁尚待现场部署。
