# 学期小组隔离升级与验收

## 已确认规则

学生组绑定教学项目（学期）及其正式村庄。332 为系统预置实验室组，长期保留成员关系；它的方案仍按学期、正式村庄分别保存，普通成员不提升为管理员。每个账号在当前学期使用一个有效组；历史学生组不阻碍新学期入组。练习村庄只有个人体验和全班共享现状，不建立小组方案。

## 历史数据处理

已有普通组只有在既有小组方案提供唯一学期/村庄证据时自动迁移。未确定归属的记录保留为 legacy，不能凭旧组码加入新学期。若一个旧普通组已经关联多个学期，预检停止，不猜测、不复制或删除成果。332 按现有已记录 ID、名称和固定组码识别。

成员和进度唯一键加入学期，旧行不删除。个人图底结果空间的唯一键也加入学期，避免同一村庄下一届复用旧结果或报历史冲突。已有方案编号不迁移；新方案采用包含学期、村庄、组的确定性编号。没有推荐冻结版本时保持等待状态。

## 升级入口

完成当前提交的原生 CI 后，在既有阿里云源码目录运行：

```bash
cd ~/village-deploy/source
git pull --ff-only origin main
python3 -B linux/scripts/repair-autonomous-semester-groups.py
python3 -B linux/scripts/repair-autonomous-semester-groups.py --apply
```

预检成功标记：`semester_groups_preflight_passed_no_service_or_data_changes`。
应用成功标记：`semester_groups_deployed_browser_acceptance_required`。

预检只读取运行配置、源码片段和函数体，不更新服务或业务数据；沿用操作器的私有诊断日志机制。应用先使用既有备份流程保存数据库与文件，再保存原 Compose 和原函数。Web 从实际正在使用的目录复制，按精确上下文片段打补丁，保留其他更新；API 只叠加 contracts.mjs。重建 API/Web，保留 Auth/Postgres 容器身份，4090 不更新。旧发布和备份不删除。

状态保存在 `~/village-autonomous/files/semester-groups-20261028-v1/`。已完成状态重复执行会验证回执。未知函数/源码、历史归属冲突、备份变化、活动任务等条件会停止。中断后保留所有回执和日志，先核对状态；不得重装、reset、删除成员或退回旧唯一键。新增多学期数据后，数据库不能通过简单删除新列来回退。

## 浏览器验收

1. 强制刷新后台“课程小组”，应显示当前学期、正式村庄；332 实验室组成员数应来自业务库。
2. 依次创建三个学生组，可指定非 332 的组码，也可留空随机生成。列表只包含本学期学生组与 332。
3. 学生用自己的账号加入对应小组；旧学期组码不能用于加入本学期。
4. 米埗村、红星村继续个人体验/共享现状流程，不出现小组方案。
5. 深井村现状冻结并推荐后，检查学生组和 332 各自的方案空间。普通成员不得进入他组；管理员通过明确的管理入口查看。
6. 归档学期后，方案编辑、冲突解决与恢复版本均拒绝继续写入。新学期同村的成员、任务进度、个人图底结果及方案重新独立建立。
