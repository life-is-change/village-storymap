# 真实场景工作台启动修复

## 原因与变化

首次创建场景时，SceneEditStudio 传入了内部 ownerId，而阿里云 scene-files 客户端直接展开整个输入对象。服务端 create 合同不接受 ownerId，返回 INVALID_INPUT / HTTP 400。客户端改为仅发送合同声明的八个字段，所有权继续由服务端认证身份确定，不放宽校验或权限。

工作台提前切换三维后，创建失败没有恢复原视图，也没有同步当前空间的二维/三维按钮。现在进入、工作台切换视图、退出均同步视图偏好和按钮；创建被拒绝、启动异常、模块缺失均隐藏工作台并恢复进入前的实际视图。

阿里云影像通过授权 blob 地址读取时，不存在可由文件名猜测的相邻 .pgw。停止为 blob/data 地址构造 world-file 请求，沿用已经提供的影像范围；普通文件地址保留原有 world-file 查询。

## 验证

修复前新增回归复现 10 个失败；修复后专项 19 项通过。最终 main 全量 1385 项通过，0 失败、0 跳过。测试使用真实服务端 parseOperation 对客户端请求进行合同校验，同时覆盖两种作用域、两种进入视图与三种失败路径。

线上更新范围仅为 app.js、app-3d.js、场景文件客户端和入口缓存版本；数据库、服务端权限及连接配置不变。部署使用既有网页挂载目录的备份与精确片段替换。线上浏览器实际结果以部署后的验收为准。
