# 学生模型与低配置运行优化

用户已确认浏览器显示优化、模型统一原点/贴地、CPU 处理模型分级的方案，并要求实施。保持原项目 main，不创建工作树；现有数据库和 GPU 队列接口不变。

1. 共享 GLB 规范化：仅从 POSITION 访问器及场景节点变换计算真实边界；为活动场景加入底部中心锚点，保持 glTF Y-up，保留原始几何/动画结构及原文件。元数据嵌入 GLB extras，不要求云端新增表字段。既有模型不强制改写。
2. 两个上传入口采用共享处理。主平台模型库同时保存原文件，场景素材保存可恢复原路径。归一化的模型直接使用底部锚点，避免包围球估算导致悬空。
3. 共享画质配置：low/balanced/high，持久保存到当前浏览器。主地图、实景窗口、照片预览使用一致配置；照片预览按需渲染并暂停隐藏页面。
4. 普通 GLB 按屏幕大小、是否选中及视野动态加载。选中对象优先；远处回退白模/简化代理；限制驻留资源和加载并发，切空间销毁过期资源。已有独立 high/low 资产可分级切换，切换不改变锚点及编辑 ID。
5. CPU 工具从原 GLB 生成规范化 high/low 文件及 manifest；不覆盖原文件，不需要 4090。支持生成版本上传到现有素材库，普通上传也可以使用代理回退。
6. 验证 POSITION/父节点/旋转缩放/偏移原点、异步加载取消、模型预算、选中远景、画质切换、刷新绑定、场景放置。先运行针对性失败测试再实现；最后完整回归及真实浏览器验证，记录实际结果与尚需目标学生设备测量的部分。

用户澄清并确认：三个入口均应接受一个 GLB，自动生成、持久保存高低版本，让其他组员自动使用。已将浏览器 CPU 处理线程接入普通模型上传、场景素材上传、照片贴图替换；离线 CLI 仅为可选开发者工具。高模保留原精度，低模目标 35% 面数/512 贴图；生成器等待确认与链接刷新配套调整。完成结果见同目录 results 文档。
