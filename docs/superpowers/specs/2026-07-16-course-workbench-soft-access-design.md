# 课程任务软访问与管理员凭据调整设计

> **过程文档：** 本文件仅用于记录本次调整的设计依据与验收边界，不属于平台运行文件。

## 1. 任务访问

采用“内容开放、共享操作受控”的软访问方式。全部七个阶段始终可见、可点击，学生不需要依次完成上一步才能查看下一步说明，也可按实际教学节奏独立标记任务完成。未加入小组时仍显示完整任务说明和完成按钮；需要写入共享小组数据的 2D/3D 规划、地图化调研资料等操作继续提示先加入小组。

## 2. 管理员权限

管理员临时凭据固定为姓名（账号）`管理员`、第二凭据 `332`。现有系统没有独立密码字段，因此第二凭据仍存储在 `studentId/student_id` 字段，但登录界面对管理员说明其作用相当于管理员凭据。所有管理员权限判断必须同时校验姓名与第二凭据；其余账号一律按普通用户处理。

## 3. Supabase

目标项目固定为 `village-storymap`，项目引用为 `rzmbmwauomzwiyenafha`。执行现有 `supabase_SQL/Task-driven Course Workbench Schema.sql`；脚本必须保持幂等，不删除现有表或数据。执行后查询 `courses`、`course_groups`、`group_memberships`、`task_progress`、`activity_events` 以及 `planning_spaces` 新字段，确认迁移成功。

## 4. 验收

- 未加入小组也能查看任意阶段完整说明并记录非共享任务进度。
- 共享地图操作仍明确要求加入小组。
- 只有 `管理员 + 332` 具有后台和跨小组编辑权限。
- SQL 在指定 Supabase 项目成功执行并通过结构查询验证。
