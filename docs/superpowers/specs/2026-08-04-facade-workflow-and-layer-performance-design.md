# 正立面工作流与 2D 图层性能修复设计

## 目标

一次修复三个相互独立但影响同一教学流程的问题：学生上传建筑实拍图后，系统先生成规范正立面预览，再允许切除屋顶并生成白模贴图建筑；本地生成服务不可用时提供明确诊断；2D 图层开关不再重建全部已显示图层。

## 3D 照片工作流

照片模式使用以下顺序：

1. 学生上传一张 JPEG 或 PNG 建筑实拍图。
2. 页面创建任务并调用新的正立面预处理接口。
3. 后端保存预处理结果和浏览器预览，任务进入 `rectified` 状态。
4. 页面用后端预览替换原始照片，此时才显示屋顶裁剪线。
5. 学生在规范正立面结果上设置屋顶下沿。
6. 页面调用主体裁剪接口，生成最终墙身贴图。
7. Blender 使用墙身贴图和所选参数生成 GLB。

原图阶段不得显示或提交屋顶裁剪值。正立面预处理失败时保留原图、隐藏裁剪线和模型生成操作，并提供重试入口。

正立面预处理复用现有“单一全局 H0＋结构保持网格”能力；自动检测结果必须保存诊断信息。若自动检测缺少足够可靠的建筑主体范围，接口返回可读错误，不在后台静默使用整张原图冒充正立面。

## 本地后端可用性

仓库提供统一的 Windows 启动脚本，同时启动 8011 后端和静态页面服务。启动脚本使用既有 `building_facade_pilot` 环境及 Blender 路径，并在启动后执行健康检查。

前端发起照片任务前先请求 `/health`。网络连接失败时显示“本地处理服务未启动或不可访问”，附带启动脚本名称；HTTP 错误继续显示后端返回的具体 `detail`。页面不得再将连接失败统一暴露为 `Failed to fetch`。

## 2D 图层增量更新

保留现有单一 `planVectorLayer`、样式函数、编辑器和 latest-wins 请求控制器，避免大范围改造编辑逻辑。

每次刷新记录当前 `VectorSource` 已包含的图层键：

- 对仍然选中的图层，直接把现有 OpenLayers Feature 复用到新 source，不重新解析 GeoJSON，也不重新查询数据库。
- 对关闭的图层，不复制其 Feature。
- 只对本次新增的图层执行静态缓存／数据库合并和 `GeoJSON.readFeature`。
- `communityTask` 等独立维护要素继续原样保留。
- 空间切换、手动刷新、实时更新或显式缓存失效时，强制完整重建，保证远端修改不会因复用而丢失。

按钮选中态应在耗时加载前立即更新。同步的大批量 Feature 构建按批次向浏览器事件循环让步，避免首次打开大图层时完全冻结。

## 错误与状态

- `uploaded`：原图已保存，尚未正立面化。
- `rectifying`：正立面预处理中。
- `rectified`：可显示处理结果并设置屋顶线。
- `preparing`：正在切除屋顶并生成墙身贴图。
- `prepared`：墙身贴图可供 Blender 使用。
- `generating` / `generated`：模型生成中／已完成。
- `error`：当前阶段失败；重试从最近的稳定产物开始。

## 测试与验收

1. 前端状态机测试证明原图上传后不能直接裁屋顶或生成模型，只有 `rectified` 后才允许。
2. API 测试证明正立面接口保存预览与诊断，主体裁剪读取正立面产物而不是原始上传文件。
3. 前端网络测试证明连接拒绝会变成明确的本地服务提示。
4. 2D 渲染测试证明关闭一个图层不会重新解析仍显示的图层，打开一个图层只构建新增层；强制刷新仍会完整重建。
5. 运行全部相关 Node 与 Python 测试。
6. 实际启动 8011 服务，通过健康检查，并在浏览器完成“上传→预处理→裁屋顶→生成 GLB”的端到端流程。
7. 在 2D 页面连续开关建筑、道路、水体等图层，按钮立即响应，快速点击只提交最新结果，页面不再长时间无响应。
