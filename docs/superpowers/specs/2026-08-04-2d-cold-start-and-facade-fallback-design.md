# 2D 冷启动与正立面预处理容错设计

## 目标

解决两个直接阻断学生操作的问题：首次进入 2D 页面长时间空白，以及建筑实拍图自动正立面化失败后流程无提示、无退路。

## 2D 页面

- OpenLayers 继续固定使用 10.8.0，改为项目本地静态资源，首屏不再发起 23 个 `esm.sh` 动态模块请求。
- 地图初始化直接采用 `BASEMAP_GEOREF` 中已经校准的范围；不再为了计算范围而预先解码 8192×4038 的 `orthophoto.webp`。
- 切换到 2D 后立即显示加载状态，地图实例创建后立刻解除空白状态；业务图层随后渐进加载。
- 正射影像只在对应底图开关实际启用时由 OpenLayers 请求。

## 建筑正立面预处理

- 保留当前严格 H0 检测作为第一阶段，避免降低现有稳定样本的质量。
- 严格检测失败时，启用第二阶段宽松检测：降低竖线最短长度，限制候选线到建筑主体中心带，并通过位置聚类选择左右边界，避免围栏和图片边缘成为边界。
- 输出诊断信息，明确记录使用 `strict` 还是 `relaxed` 检测。
- 两阶段均失败时不再让界面进入死状态。保留原始预览，显示中文说明，并提供“使用原图继续”和“重新选择照片”。
- 上传后的状态明确显示为“上传照片、识别建筑、生成正立面、裁剪屋顶、生成模型”。只有正立面成功后才显示屋顶裁剪线；选择原图继续时也允许进入屋顶裁剪步骤，但明确标注未完成自动校正。

## 验证

- Node 测试覆盖 2D 初始化不再依赖正射影像尺寸读取、加载状态及时显示，以及失败回退状态。
- Python 测试覆盖严格检测失败后宽松检测成功，并使用本次实际上传照片回归。
- 浏览器冷启动验证首次进入 2D 不再出现 30 秒空白；建筑生成器验证上传、进度、成功与失败回退路径。
