# 学期小组与 332 实验室组隔离

用户已确认规则并要求直接修改。普通小组属于具体教学项目（学期），并使用该项目的正式村庄；不能按课程模板混用。332 为管理员预置的唯一实验室组，普通成员不获得管理员角色。实验室组成员跨学期保留，方案仍按学期、正式村庄、组分别建立。所有练习村庄禁止小组方案，个人体验与全班共享现状继续按学期和村庄区分。

## 方案

采用数据库显式学期归属与服务端权限校验。仅前端过滤不能阻止旧组码和直接 API 越权；按村庄独立建组无法隔离同村不同届教学，均不采用。

- 普通组保存 teaching_project_id 与 formal_village_id；固定归属，禁止归档学期新入组或写入。
- 332 保存系统实验室标识，不依靠输入数字 332 判断管理员角色。客户端不能创建另一个实验室组或指定特权标识。
- 成员资格每学期唯一；332 为独立长期成员资格。旧学期关系保留，不占用新学期入组资格。
- 课程小组、成员统计、进度和活动从同一业务 API 按当前项目读取，明确显示当前学期、正式村庄和实验室组类型。
- 方案编号包含学期和村庄；同一个实验室组不能复用上一学期的空间编号或基线。
- 旧普通组只有在既有方案提供唯一归属证据时迁移；未确定归属的旧组保留为 legacy，不自动授予新学期资格。现有 332 组按已记录精确身份迁移。
- 个人图底历史存储唯一键加入学期，防止复用课程模板时冲突；不移动或覆盖已有成果。
- 发布 V0 不等于冻结基线；无推荐冻结时保持等待状态，不能假报空间建立成功。

## 验收

两学期同一课程、同村/不同村均隔离；同账号可在新学期加入新组；旧组码不能加入当前学期；跨组/跨村/跨学期请求被服务端拒绝；332 普通成员不能管理用户、村庄或他组方案；练习村庄拒绝创建方案；管理员身份不变。升级保留已有村庄、照片、成员、基线与实验数据。先通过本地检查及独立原生 Postgres 测试，再准备受控升级，不能以静态测试代替线上验收。
