# 多村庄双轨空间体系第一阶段设计

**日期：** 2026-09-02  
**状态：** 已完成需求确认，待用户审阅  
**范围：** 村庄注册、正式村庄绑定、练习/正式项目切换、空间隔离、动态二维/三维数据上下文  
**主入口：** `/index.html`

## 1. 背景与目标

平台目前围绕米埗村建立了理论学习、个人图底生产、全班现状校核、二维地图、三维白模、村庄实景对照和小组方案设计等能力。现有前端仍有较多米埗村固定配置，空间也主要依赖全局名称和当前空间状态进行区分，不能安全承载新的正式课程村庄。

第一阶段的目标是建立稳定的“教学项目—村庄—空间—数据版本”关系，同时保持米埗村现有功能可用。管理员可以创建并绑定一个新的正式村庄，全班所有小组共同规划该村庄；学生可以在米埗村练习项目与正式课程项目之间切换，两边的数据完全隔离。

本阶段采用双轨空间体系：个人空间用于体验和试验，共享现状空间用于正式协作。个人空间中的生成、编辑和删除不会反馈到共享现状空间，只有共享现状空间中的修改才能进入后续校核版本和小组方案基线。

## 2. 已确认的产品原则

1. 米埗村是长期保留的公共练习村庄。
2. 米埗村每个教学学期生成独立的全班共享现状空间，历届修改、照片、问题和日志不混用。
3. 一个教学项目最多绑定一个正式村庄，所有小组共同规划同一个正式村庄。
4. 正式村庄发布前可以只有二维建筑矢量，不要求同时提供村庄级三维实景模型。
5. 二维建筑面进入主 Cesium 场景后自动挤出白模：优先采用建筑高度字段，其次按层数乘以 3 米，均缺失时使用 9 米。
6. 村庄级实景模型沿用米埗村现有结构，在独立的 Cesium Viewer 中作为实景对照加载，不替换、不遮挡主场景白模。
7. 管理员可以在学期中期为正式村庄补充 Cesium ion Asset ID，预览、校准高度后发布，不影响已经存在的二维数据、白模和小组方案。
8. 正式村庄初始数据由管理员使用与学生相同的图底生产流程生成，或上传本地处理结果；不汇总学生个人空间成果。
9. 管理员发布的是可供学生开始校核的原始 V0，不要求管理员逐个修正建筑矢量。后续校核与属性、照片、问题补充是学生在共享现状空间中的任务。

## 3. 术语与层级

### 3.1 教学项目

教学项目是一个学期的数据容器，负责隔离当届学生、小组、空间、调研数据、版本和操作日志。第一阶段不建设通用课程内容编辑器，只保留一个可配置的当前教学项目。

### 3.2 村庄

村庄是可复用的空间对象，保存名称、练习属性、边界和基础数据版本。同一个米埗村可以在不同教学项目中生成互相隔离的共享练习空间。

### 3.3 数据版本

村庄基础数据版本保存管理员生成或上传的影像与矢量成果。发布后的 V0 不可变。学生修改以空间覆盖记录、修改批次和后续快照的形式保存，不直接改写 V0。

### 3.4 空间类型

| 空间类型 | 适用村庄 | 归属 | 作用 | 是否进入正式成果 |
| --- | --- | --- | --- | --- |
| `practice_personal` | 米埗村 | 单个学生 | 图底生成、参数试验、矢量编辑体验 | 否 |
| `practice_shared` | 米埗村 | 当届全班 | 多人现状校核与协作练习 | 否 |
| `formal_personal` | 正式村庄 | 单个学生 | 自由体验和试验 | 否 |
| `formal_shared` | 正式村庄 | 当届全班 | 正式调研、现状校核和版本形成 | 是 |
| `group_plan` | 正式村庄 | 单个小组 | 基于冻结现状版本开展方案设计 | 是 |

米埗村不创建 `group_plan`。正式村庄的 `group_plan` 只有在教师或管理员冻结正式现状版本后才创建或开放。

## 4. 学生端信息架构

学生端采用“项目切换器 + 空间切换器 + 2D/3D 视图切换”的三级上下文，不使用一个混合下拉框同时罗列全部村庄和空间。

### 4.1 项目切换器

顶部情境栏显示当前项目。展开后按两组展示：

- 正式课程项目：显示正式村庄名称和当前阶段；正式村庄未开放时显示不可进入状态。
- 练习项目：显示米埗村和“公共练习”标识。

正式村庄未发布时，学生默认进入米埗村。正式项目首次开放后显示一次通知，此后默认进入正式项目，但仍可返回米埗村练习。

### 4.2 空间切换器

米埗村只显示“我的个人体验空间”和“全班共享现状空间”。

正式村庄显示“我的个人体验空间”“全班共享现状空间”，并在正式现状冻结后显示“本小组方案空间”。

界面持续显示空间属性标签：`练习`、`正式课程`、`仅自己可见`、`全班共享`或`组内共享`。

### 4.3 切换事务

项目切换按以下顺序执行：

1. 检查当前空间是否存在未保存编辑。
2. 有草稿时要求学生保存或放弃，未处理前不允许切换。
3. 清除当前对象选择、编辑工具和临时预览。
4. 卸载上一村庄的二维图层与三维数据源。
5. 关闭并销毁上一村庄的实景对照 Viewer。
6. 加载目标村庄边界、数据版本和学生可访问空间。
7. 恢复学生在该项目上次使用的空间和 2D/3D 视图。
8. 所有资源加载成功后提交上下文切换；失败时保留原项目。

## 5. 管理员端信息架构

后台新增一级菜单“村庄与项目”，包含“村庄库”和“当前教学项目”。

### 5.1 村庄库

列表显示村庄名称、练习/正式属性、数据状态、V0 发布时间、当前项目绑定状态和实景模型状态。管理员可以新建村庄、继续准备数据、预览、发布 V0、绑定为正式村庄、添加实景模型，以及删除未发布草稿。

### 5.2 当前教学项目

显示当前教学项目名称、练习村庄、正式村庄、正式项目开放状态、共享现状版本和三维实景状态。管理员可以绑定正式村庄、开放或关闭正式项目、进入共享现状、管理实景模型和归档学期。

## 6. 管理员创建和发布村庄流程

### 6.1 最小创建字段

管理员只填写：

- 村庄名称；
- 是否为练习村庄；
- 村庄大致范围。

村庄内部 ID 由系统生成，不向管理员要求编码。行政区和简介不属于第一阶段。默认坐标系使用平台与米埗村相同的配置，普通界面不展示，仅在高级设置中允许修改。

### 6.2 村庄范围输入

村庄范围是必填数据，支持：

1. 在地图上绘制多边形；
2. 上传 GeoJSON；
3. 上传 Shapefile ZIP，至少包含 `.shp`、`.shx`、`.dbf` 和 `.prj`。

所有来源最终转换为 EPSG:4326 的 Polygon 或 MultiPolygon 存储。Shapefile 缺少 `.prj` 时可以按平台默认坐标系尝试解析，但必须要求管理员确认位置。多面边界在第一阶段自动合并为一个 MultiPolygon。

系统检查空几何、非面要素、投影异常、无效几何、异常经纬度和明显异常面积，并显示边界面积、坐标范围和初始地图视角。管理员确认位置正确后才能创建村庄草稿。

### 6.3 初始数据准备

首选路径是管理员使用现有个人图底生产能力：村庄边界作为默认 AOI，管理员可以缩小处理范围，提交建筑识别、道路水系提取和等高线生成任务，完成后预览结果。

备用路径是上传本地处理结果。第一阶段支持统一 GeoJSON 数据包，包含建筑、道路、水系和等高线；完整的多图层 Shapefile 字段映射工作台不在本阶段范围内。

两条路径均进入同一个数据预览和发布流程。管理员不需要在发布前逐栋修正建筑。

### 6.4 V0 发布

发布前显示影像、各图层要素数量、数据范围、缺失图层警告和默认三维白模预览。建筑图层为必需项；道路、水系和等高线可以缺失，但必须明确提示。

发布必须是原子操作：完整数据版本成功写入后才生成不可变 V0，任何一步失败都保持村庄草稿状态，不能产生半发布数据。

### 6.5 正式村庄绑定

只有存在已发布 V0 的村庄可以绑定。一个教学项目最多绑定一个正式村庄，绑定成功后自动创建正式村庄的全班共享现状空间；学生个人体验空间在首次进入时按需创建。小组方案空间在现状冻结前不创建。

正式项目开放且已经产生学生修改后，不允许直接更换或解绑正式村庄。需要更换时必须关闭并归档原教学项目，建立新的教学项目数据容器。

## 7. 核心数据模型

### 7.1 `villages`

- `id uuid primary key`
- `name text not null`
- `is_practice boolean not null default false`
- `boundary geometry(MultiPolygon, 4326) not null`
- `default_crs text not null default 'EPSG:4326'`
- `status text not null`：`draft`、`data_preparing`、`data_ready`、`published`、`archived`
- `created_by uuid not null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

### 7.2 `village_datasets`

- `id uuid primary key`
- `village_id uuid not null`
- `version_number integer not null`
- `version_label text not null`
- `source_kind text not null`：`platform_generated` 或 `uploaded_bundle`
- `imagery_config jsonb`
- `layer_manifest jsonb not null`
- `status text not null`：`draft`、`validating`、`ready`、`published`、`failed`
- `created_by uuid not null`
- `created_at timestamptz not null`
- `published_at timestamptz`

`layer_manifest`只保存受控的存储路径、图层类型、要素数量、坐标系和校验摘要，前端不能通过任意 URL 注入外部数据。

### 7.3 `teaching_projects`

- `id uuid primary key`
- `name text not null`
- `practice_village_id uuid not null`
- `formal_village_id uuid`
- `formal_project_open boolean not null default false`
- `stage text not null`：`preparing`、`survey`、`design`、`completed`、`archived`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

第一阶段只维护一个当前活动教学项目，不建设课程内容编辑器。

### 7.4 规划空间扩展

现有规划空间增加或规范以下字段：

- `teaching_project_id uuid not null`
- `village_id uuid not null`
- `base_dataset_id uuid not null`
- `space_type text not null`
- `owner_id uuid`
- `group_id uuid`
- `readonly boolean not null`

唯一性规则保证同一教学项目、村庄、学生和空间类型只生成一个个人空间，同一教学项目和村庄只生成一个共享现状空间。

### 7.5 `village_reality_models`

- `id uuid primary key`
- `village_id uuid not null`
- `ion_asset_id bigint not null`
- `title text not null`
- `height_offset double precision not null default 0`
- `terrain_enabled boolean not null default true`
- `status text not null`：`draft`、`validating`、`ready`、`published`、`disabled`
- `created_by uuid not null`
- `created_at timestamptz not null`
- `published_at timestamptz`

每个村庄最多有一个当前已发布实景模型，旧版本保留记录但不默认加载。

## 8. 二维与三维数据规则

### 8.1 动态二维数据上下文

二维地图不再固定读取米埗村路径。运行时根据 `teaching_project_id + village_id + space_id` 解析当前数据版本、基础影像、图层清单和空间覆盖记录。

照片、问题、讨论、要素修改、版本快照和活动日志均必须携带教学项目 ID、村庄 ID 和空间 ID。服务端 RLS 依据项目成员、空间类型、个人归属和小组成员关系控制访问。

### 8.2 主三维白模

主 Cesium Viewer 读取当前空间中的有效二维建筑面：

1. 优先读取建筑高度字段；
2. 未提供高度时读取层数并乘以 3 米；
3. 均未提供时使用 9 米；
4. 获取到地形高程时以地形高程作为建筑底部；
5. 建筑轮廓或高度修改后只重载受影响的白模或当前建筑数据源。

村庄边界和数据范围用于计算初始相机视角，不能继续使用米埗村固定坐标和固定飞行范围。

### 8.3 村庄实景对照

村庄实景模型在独立 Cesium Viewer 中加载，与主白模场景并行存在。当前固定的 `window.VILLAGE_REALITY_MODEL` 配置改为从活动村庄的已发布资源动态读取。

管理员在 Cesium ion 外部上传并处理村庄级模型，然后在平台填写 Asset ID，进入独立实景窗口预览，调整高度偏移并发布。项目切换时销毁旧村庄实景 Viewer，并根据新村庄配置重新创建；未配置或加载失败时隐藏实景入口，主白模继续正常工作。

### 8.4 单栋建筑替换模型

现有 GLB 模型库和建筑绑定继续服务个人体验空间与正式小组方案空间，不属于村庄级实景模型。村庄级实景资源对全班只读，单栋替换模型按个人或小组空间隔离。

## 9. 权限规则

- 学生只能查看当前教学项目的米埗村练习实例和已开放的正式村庄。
- 学生可读写自己的个人体验空间。
- 当前教学项目全体学生可参与对应的共享现状空间；写入仍经过对象锁和显式保存流程。
- 学生只能访问自己所属小组的方案空间。
- 教师和管理员可查看当前教学项目的全部空间和版本。
- 只有管理员可以创建村庄、准备或上传 V0、绑定正式村庄和配置 Cesium ion 资源。
- 管理员与教师可以冻结正式现状版本；具体教师角色权限沿用可信数据库角色判断。
- 发布后的村庄 V0 和已冻结现状版本对学生只读。

## 10. 迁移与兼容策略

1. 将当前米埗村注册为 `is_practice = true` 的村庄，并把现有静态影像、建筑、道路、水系和等高线登记为米埗村 V0。
2. 建立当前活动教学项目，并将米埗村绑定为练习村庄。
3. 将当前全局现状空间迁移为该教学项目下的 `practice_shared`；现有学生个人图底空间迁移为 `practice_personal`。
4. 为原有照片、问题、讨论、要素修改、版本和活动记录补齐当前教学项目与米埗村标识。
5. 在前端增加统一的活动上下文服务，逐步替换 `mibu`、固定 GeoJSON 路径、固定影像范围和固定实景 Asset ID。
6. 迁移期间保留兼容适配器，将旧的 `current` 和 `current_3d` 逻辑解析到当前活动上下文；新功能不得继续产生没有项目与村庄标识的数据。
7. 旧数据迁移和索引创建必须可重复执行，并在远程执行前验证记录数、孤立数据和唯一性冲突。

## 11. 异常处理与安全约束

- 项目切换失败时保留原项目和原空间，不提交部分上下文。
- 有未保存编辑时禁止切换项目。
- 图底处理服务离线时允许排队，失败时村庄保持草稿。
- 缺少建筑图层时禁止发布 V0；其他图层缺失时允许发布但必须警告。
- 一个教学项目已有正式村庄时禁止绑定第二个。
- 正式项目开放并产生学生数据后禁止解绑或替换村庄。
- Cesium ion Asset ID 不可访问时禁止发布；实景加载失败不得阻塞主三维白模。
- 新实景版本发布失败时继续保留上一个已发布版本。
- 数据包、边界文件和存储路径必须经过类型、大小、坐标、几何和权限校验。
- Cesium ion Token 不作为村庄记录明文存储；使用平台级安全配置，村庄只保存 Asset ID 和展示参数。

## 12. 第一阶段验收标准

### 12.1 管理员端

- 能创建只有名称、练习属性和边界的村庄草稿。
- 能绘制范围，或上传 GeoJSON、Shapefile ZIP 边界。
- 能预览范围、面积和初始视角并确认位置。
- 能通过平台现有图底流程生成初始数据，或上传本地 GeoJSON 数据包。
- 能预览二维图层和按现有规则生成的白模。
- 能原子发布不可变 V0。
- 能将一个已发布村庄绑定为全班共同的正式村庄。
- 能在学期中期配置 Cesium ion Asset ID、预览、调整高度偏移并发布实景模型。

### 12.2 学生端

- 能在当届米埗村练习项目和正式村庄之间切换。
- 米埗村只显示个人体验空间和当届全班共享现状空间。
- 正式村庄在现状冻结前显示个人体验空间和全班共享现状空间。
- 冻结现状后仅显示学生所在小组的方案空间。
- 个人空间中的任何操作均不影响共享现状。
- 不同村庄、学期和空间之间的照片、问题、讨论、修改、版本与日志完全隔离。
- 二维建筑能在三维主场景中按明确高度、层数乘以 3 米或默认 9 米形成白模。
- 正式村庄无实景模型时白模正常工作，中期发布实景后出现独立实景对照入口。

### 12.3 回归要求

- 根目录 `/index.html` 继续作为唯一主入口。
- 米埗村现有二维地图、白模、实景对照和建筑选择联动不退化。
- 登录、个人中心、加入小组、课程阶段、个人图底生产、对象编辑、照片、问题和讨论继续工作。
- 2D/3D 切换继续共享当前空间与对象上下文。
- 现有对象锁、显式保存、修改历史和冻结版本机制继续有效。

## 13. 第一阶段不包含的内容

- 学生个人成果合并或同步到共享现状。
- 同一个教学项目绑定多个正式村庄。
- 通用课程内容编辑器和多课程选课系统。
- 完整的多图层 Shapefile 字段映射工作台。
