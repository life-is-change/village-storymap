# 照片生成服务恢复与精细屋顶设计

## 目标

改造乡村建筑 3D 生成器，使照片模式在本地 AI 服务暂时不可用时能够持续检测服务状态，并在服务恢复后允许用户一键重新处理当前照片。同时提升照片模式生成屋顶的完成度，让四坡、双坡和平屋顶都具备基本建筑构造和可辨识材质，而不是无厚度的纯色面片。

本次改造追求可信、完整和流畅的乡村建筑表达，不追求从单张照片精确反演复杂屋顶，也不增加屋顶参考图上传。

## 范围

### 包含

- 照片模式进入时立即检查 `http://127.0.0.1:8011/health`。
- 服务不可用时显示明确状态，并在照片模式可见期间周期性重新检查。
- 服务从不可用恢复为可用时显示“服务已恢复，重新处理当前照片”操作。
- 重新处理沿用浏览器内仍然保留的当前照片，不再次打开文件选择器。
- 请求期间再次断线时重新进入等待服务状态。
- 四坡屋顶增加屋面厚度、主屋脊、四条斜脊、压瓦、四周檐口、封檐板和基础排水沟。
- 双坡屋顶增加屋面厚度、主屋脊、压瓦、山墙封边、檐口和基础排水沟。
- 平屋顶增加薄屋面、女儿墙和压顶。
- 提供灰瓦、沥青瓦和陶瓦三种屋面材质。
- 提供低坡、标准坡和高坡三档坡度。
- 按建筑进深与坡度计算屋脊高度，按屋面真实距离铺设纹理，防止瓦片被拉伸。
- 预览和导出的 GLB 使用同一份后端生成结果。

### 不包含

- 不从单张正立面照片自动推断复杂屋顶拓扑。
- 不生成老虎窗、交叉屋面、天沟交汇、烟囱、真实椽架或室内屋架。
- 不直接使用用户照片作为屋顶纹理。
- 不让浏览器自动执行本地 `.bat` 或启动系统进程。
- 不在服务恢复时自动提交耗时任务。

## 用户体验

### 服务状态

照片模式增加一个紧凑的服务状态区，状态包括：

- `检测服务中`：首次进入或重新检测期间。
- `本地服务可用`：健康检查成功，可以选择并处理照片。
- `本地服务未启动`：健康检查失败，显示运行 `start_facade_generator.bat` 的说明。
- `服务已恢复`：此前离线、当前健康，并且浏览器仍保留失败时选择的照片；显示“重新处理当前照片”按钮。

轮询只在页面可见且处于照片模式时运行。健康状态稳定为可用且没有待恢复照片时停止频繁轮询；任何网络请求失败会重新启动轮询。轮询不得自动创建任务或调用模型推理。

用户点击“重新处理当前照片”后，界面清除旧错误并从照片上传阶段重新开始。若浏览器已不再持有照片文件，则退化为“重新选择照片”。

### 屋顶配置

现有“生成屋顶”类型选择保留，并增加两个简单字段：

- 屋顶材质：灰瓦、沥青瓦、陶瓦。
- 屋顶坡度：低坡、标准坡、高坡。

不向用户暴露米制屋脊高度、纹理重复次数或构件厚度等工程参数。默认组合为“四坡屋顶 + 灰瓦 + 标准坡”，允许用户为接近原貌切换为平屋顶。

## 数据与接口

照片任务的建筑配置增加两个有默认值的字段：

- `roof_material`: `gray_tile | asphalt_shingle | terracotta_tile`，默认 `gray_tile`。
- `roof_pitch`: `low | standard | high`，默认 `standard`。

前端创建任务时随现有屋顶类型一起提交。后端在任务 JSON、准备结果、Blender 配置和 `model_manifest.json` 中保留这两个字段。旧任务或旧调用未提供字段时采用默认值，保持兼容。

坡度档位对应固定角度：

- 低坡：18°。
- 标准坡：26°。
- 高坡：34°。

坡屋顶高度使用横向半跨与坡度角计算，并设置合理的最小值。四坡屋顶的屋脊方向沿建筑较长轴布置。出檐、屋面厚度、封檐板、脊瓦和排水沟尺寸由统一的屋顶参数函数根据建筑尺度计算，并限制在适合网页模型的范围内。

## Blender 屋顶生成

屋顶生成拆分为两层：

1. 纯 Python 参数层负责将建筑尺寸、屋顶类型、坡度档位和材质档位解析为确定的尺寸及颜色配置，便于普通单元测试覆盖。
2. Blender 构建层根据参数生成屋面、脊线、檐口、排水沟和材质，并导出 GLB。

每个坡面具有独立、方向一致的 UV。瓦片纹理由生成脚本创建并嵌入 GLB，包含基础色变化、瓦片分缝和适度粗糙度；不依赖外部网络资源。凹凸仅用于细微表面层次，不能替代屋脊、斜脊和檐口等真实几何构件。

为保持交互性能，瓦片不逐块建模。屋脊、斜脊、封檐板、女儿墙和排水沟使用少量独立网格；生成结果应保持在适合浏览器实时预览的网格规模内。

## 错误处理

- 健康检查仅代表进程可访问，不将模型的延迟加载状态误报为故障。
- 健康检查设置短超时，失败不会覆盖已经选择的照片。
- 用户手动重新处理期间禁用恢复按钮，防止双击创建并行任务。
- 后端返回业务错误时继续显示具体错误，并保留“使用原图继续”流程。
- 只有网络不可访问错误才切换到服务等待状态；图像识别失败不会被误判为服务离线。
- Blender 生成失败仍保留现有错误日志和 HTTP 错误，不返回伪成功 GLB。

## 测试与验收

### 自动测试

- Node 单元测试覆盖服务状态转换、待恢复照片判定、恢复按钮文案以及新增屋顶字段映射。
- 后端测试覆盖新增字段默认值、合法枚举、任务持久化和准备阶段保留字段。
- 纯 Python 单元测试覆盖三档坡度、屋脊高度、出檐与构件尺寸边界。
- Blender 端到端测试验证 GLB、清单字段和不同屋顶类型的关键对象名称。
- 现有照片工作流、上传、裁剪、生成和启动器测试全部保持通过。

### 视觉验收

- 四坡屋顶从正前方和斜上方均能看到瓦片尺度、主屋脊、斜脊、檐口厚度与封边，不再呈现为灰色薄板。
- 双坡屋顶能看到屋脊、山墙封边和有厚度的檐口。
- 平屋顶能看到女儿墙与压顶，并保持整体厚度克制。
- 三种材质在普通预览距离下可明显区分，纹理不横向拉伸或在相邻坡面方向错乱。
- 默认屋顶在现有示例建筑上不遮挡二层立面，也不与墙体产生明显悬空或穿插。
- 导出 GLB 重新加载后与首次预览一致。
- 服务离线时选择照片，随后启动服务，页面能够显示恢复按钮；点击后成功进入照片处理流程。

## 兼容与性能约束

- 保持现有 `roof_type` 值和照片任务 API 路径不变。
- 新字段具有默认值，旧前端与旧任务文件可继续使用。
- 不增加新的网络依赖或运行时第三方包。
- 生成的材质图片嵌入 GLB，下载后无需外部纹理文件。
- 服务状态轮询不得在预设模式或后台标签页持续运行。
