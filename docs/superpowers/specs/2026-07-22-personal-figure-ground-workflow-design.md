# 个人图底生产、版本管理与村庄预览设计

## 目标

让学生独立完成从研究范围绘制、建筑识别、道路水系提取、等高线生成，到成果预览、导入个人空间、手工修订和图底关系合成的完整流程。系统继续采用 GitHub Pages 静态前端、Supabase 队列与 Storage、Win11 出站 Worker 的架构。

## 已确认的产品决策

- 学生提交任务后先预览成果，再主动保存到个人空间，不自动覆盖现有成果。
- 每名学生在每门课程、每个村庄下只有一个个人空间。
- 每次导入形成新的图层版本；学生可切换、比较和删除自己的旧版本。
- 当前版本中的建筑、道路和水系允许继续手工编辑。
- 等高线允许显示、隐藏、切换版本和删除版本，暂不进入普通几何编辑工具。
- 图底关系是建筑、道路、水系和等高线当前版本的动态组合，不复制一份重复几何。
- 学生本人可查看和编辑个人空间；教师与管理员可查看；其他学生不可访问。
- 个人成果不会自动共享给小组。后续由学生明确选择版本提交给小组。
- 农田和公共空间退出当前教学版本；历史数据库记录保留但不再加载，避免破坏性迁移。
- 村庄 TIF 的网页预览可以公开存放在 GitHub Pages。

## 方案比较

### 采用：单一个人空间中的图层版本

每次处理任务形成一个成果批次，各图层版本关联同一 `run_id`。空间保持稳定，学生可独立选择各图层当前版本并手工编辑。该方案最符合连续试验、比较和后续小组提交需求。

### 不采用：每次任务创建新空间

可以复用既有空间逻辑，但多次试验会产生大量空间，版本关系和小组提交都不清晰。

### 不采用：覆盖当前图层并仅保留隐藏快照

界面简单，但学生无法直观管理识别试验，也无法按图层删除旧版本。

## 村庄数据与公开预览

`server/config/villages.yaml` 继续作为服务器原始数据目录，记录影像 TIF、DEM、OSM、模型参数和地理范围。新增预览生成命令：

1. 读取指定村庄的原始 TIF。
2. 转换到网页可用的 RGB WebP，限制最长边和文件大小。
3. 从栅格仿射变换计算 WGS84 地理范围；必要时重投影。
4. 输出到 `assets/villages/<village_id>/preview.webp`。
5. 生成可提交 Git 的 `assets/villages/catalog.json`，包含村庄 ID、名称、预览路径、范围和预览生成时间。

原始 TIF、DEM、OSM、模型和绝对路径不进入 Git。换村时运行一次生成命令并提交预览与目录文件。

学生点击“在二维地图绘制范围”后，前端按当前课程的 `villageId` 加载对应预览、切换到二维视图、缩放到村庄范围并启用一次性多边形绘制。AOI 完成图层固定渲染在影像上方；页面显示面积、合法性以及“重新绘制”。

## 任务与成果预览

地理处理面板挂载时调用 `listMine(villageId)` 恢复当前学生的历史任务，而不是只保存本次页面内存状态。任务卡显示状态、参数、提交时间、要素数量和警告。

完成任务后读取五类 artifact：

- `buildings`
- `roads`
- `waterways`
- `water_areas`
- `contours`

“在地图中预览”通过短期签名 URL 下载 GeoJSON，仅加入临时预览图层，不写入个人空间。不同成果使用与正式图层一致的样式，学生可以分别开关。预览失败不会改变空间数据；签名过期时自动重新申请一次。

## 个人空间

首次进入课程时通过安全 RPC 幂等创建个人空间，唯一键为 `(owner_id, course_id, village_id, space_type='course_personal')`。空间标题默认为“<学生姓名> · 个人图底空间”，初始图层为空。

权限规则：

- owner 可以读取、编辑、导入和删除自己的版本与要素。
- teacher/admin 可以读取所有个人空间及版本，不默认取得编辑权。
- 其他 authenticated 用户不能读取。
- anon 无权访问个人空间及成果。

前端不能传入或覆盖 `owner_id`。RPC 从 `auth.uid()` 和可信 profile role 判定身份。

## 导入与版本模型

学生在成果预览中点击“保存到我的个人空间”。服务器端 RPC 验证：任务属于当前用户、状态为 completed、artifact 属于该任务、目标空间属于当前用户且课程和村庄一致。

导入映射：

- `buildings` → `building`
- `roads` → `road`
- `waterways` 与 `water_areas` → `water`
- `contours` → `contours`

一次任务导入形成一个 `result_bundle`；每个实际存在的目标图层形成一个 `layer_version`。要素保存 `space_id`、`layer_key`、`layer_version_id`、稳定对象编码、几何、属性和来源 artifact。导入使用事务和唯一约束保证重复点击不会重复写入。

新版本导入后默认设为相应图层的当前版本，但不会删除旧版本。学生可以：

- 切换当前版本。
- 以半透明方式比较一个旧版本。
- 删除非当前旧版本。
- 先切换当前版本再删除原当前版本。

手工编辑直接作用于当前版本，并继续使用现有对象级锁、编辑记录和快照机制。等高线版本保持只读。删除版本采用数据库事务；若版本仍是小组提交来源则拒绝删除并给出说明。

## 图底关系

`figureGround` 保持虚拟组合模式。启用后读取个人空间当前的 `building`、`road`、`water` 和 `contours` 版本，以统一的图底关系样式渲染：建筑为主要“图”，道路与水系构成空间骨架，等高线作为地形背景。任一当前版本或要素编辑发生变化后，组合视图即时刷新。

图底关系模式只保存显示选择，不创建重复要素，避免源图层修改后组合结果失步。

## 农田和公共空间删减

本阶段移除：

- `data/croplands.*` 与 `data/open_spaces.*` 静态文件。
- 图层菜单、默认图层、编辑工具和复制空间初始化中的 `cropland`、`openSpace`。
- 仅服务于这两类图层的缓存、适配和 UI 分支。

保留通用 `planning_features` 表及其中可能存在的历史行；不执行数据库物理删除。社区问题类型中的“公共空间需求”属于调查内容，不等同于公共空间矢量图层，继续保留。

## 错误处理

- 预览目录或图片缺失：提示教师尚未生成当前村庄预览，不回退显示其他村庄。
- AOI 越界、过大或无效：保留已绘范围并显示具体原因。
- Worker 离线：允许排队并持续显示任务；恢复后继续处理。
- 页面刷新：从 Supabase 恢复任务、artifact、个人空间和当前版本。
- 部分 artifact 为空：允许导入其他成功图层，并在对应图层显示空结果警告。
- 导入失败：事务回滚，不留下半个版本。
- 重复导入：返回已存在的 bundle，不重复写入要素。
- 删除当前版本或已提交版本：拒绝并提示先切换或解除提交关系。

## 数据库安全迁移

新增表和 RPC 采用 RLS，替代旧规划空间与规划要素的宽松策略。迁移只为个人空间和版本化要素启用严格 owner/course/village 约束，不在浏览器暴露 service role。教师和管理员通过可信 `profiles.role` 获得只读审阅权限。

旧的系统现状空间和既有小组空间保留兼容路径，避免本次改造破坏已有协作功能。

## 测试与验收

### 自动测试

- TIF 预览生成尺寸、坐标范围和目录输出。
- AOI 图层位于影像之上，闭合后保留且退出绘制模式。
- 页面刷新后恢复本人历史任务和完成成果。
- artifact 到平台图层的映射与水系合并。
- 个人空间幂等创建。
- 重复导入幂等、失败事务回滚。
- 版本切换、比较、删除约束。
- 图底关系仅使用当前版本并随编辑刷新。
- RLS：本人可编辑、教师管理员可读、其他学生与 anon 不可读。
- 农田与公共空间不再出现在当前教学版本入口。

### 端到端验收

1. 学生登录后自动看到空的个人空间。
2. 点击绘制时加载当前村庄公开预览，AOI 闭合后保持可见。
3. 提交建筑、道路水系、等高线任务，刷新页面后仍能看到进度。
4. 完成后在地图预览全部成果和要素数量。
5. 主动保存到个人空间，四类图层立即出现并形成图底关系。
6. 手工修改建筑、道路或水系后图底关系同步更新。
7. 再次处理并导入，旧版本保留，可比较、切换和删除。
8. 另一学生无法读取该空间，教师管理员可以查看。
