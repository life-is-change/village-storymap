## 2. 采用的架构

网页 → 同源阿里云API → PostgreSQL、私有文件
校园4090 Worker → 主动HTTPS请求阿里云API → 领取/续租/状态/文件
阿里云API → 网页SSE/有界轮询 → 进度和完成通知

复用已实现的普通业务API、权限、场景、文件存储、连接池和大部分前端任务接口；新增本地任务调度及Worker网关。旧Supabase网关保留为兼容模式，默认不因代码更新切换运行环境。已完成的旧镜像保留，不能复用其版本标签声称为本方案。

不在2GB机器运行全套Supabase。任务领取与续租用PostgreSQL原子事务/行锁与租约；不新增Redis/RabbitMQ或本地GPU推理服务。任务等待、文件传输和SSE不长时间占用数据库连接。

## 3. 队列、授权与数据一致性

- 分图底、立面任务类别；客户端固定操作接口，提交编号与身份/上下文/输入摘要绑定，丢响应重放不得重复生成任务。
- 独立Worker身份凭据放私有文件/受限环境，限定实例和任务类别；浏览器令牌无Worker权限，Worker凭据无普通用户任意表读写权限。不同凭据可撤销，日志不含凭据/业务行。
- 领取使用原子SKIP LOCKED和服务端lease token；进度、续租、上传与完成均核对有效租约及任务归属，过期Worker不能覆盖新Worker结果。保留取消、重试、幂等完成、过期回收和最大尝试数。
- 本地队列只接受明确的新本地任务。新快照中的旧Supabase队列表仅作历史参考，不能启动消费者重放已有/运行中/计费任务。
- Worker只访问固定HTTPS源和固定文件ID接口；不接受任意URL/路径。下载校验类型、大小、摘要，上传流式写入私有暂存，完整文件验证后原子提交；失败保留可检查状态并清理无引用暂存，绝不删除已引用结果。
- 图底结果导入使用本地任务ID、产物摘要及目标个人空间幂等收据；生成物展示和导入检查当前权限，拒绝越权、失效项目/空间、重复应用和旧响应。
- 立面原有矫正→裁切确认→生成→文件展示流程保留；输入照片、任务状态、生成版本和结果均属于阿里云。断线重试不产生重复任务或错误完成。
- 既有云端立面提供商功能若在当前页面启用，其任务控制/结果也本地管理，提供商调用由阿里云后端完成；密钥只在服务端隐藏录入，计费请求的未知结果不得自动重提。真实付费验收仍需用户明确授权，未验证时不能记全流程通过。

## 5. 公网IP与HTTPS

当前前端在公网HTTP下明确拒绝aliyun模式，不能通过删除HTTPS检查让用户登录令牌/Worker凭据走明文。

2026年Let’s Encrypt已公开支持IP证书。采用Certbot5.4+的IP/webroot支持申请受信任证书，证书SAN必须是 `8.148.248.237`。先验证ACME临时环境，再申请生产证书，不能把临时证书当成受信任证书。

新增只读ACME challenge路径与私有证书安装/自动续期流程；HTTP challenge可达性、80/443端口、CA出网连接需要真实检查。IP证书有效期约6天，必须验证自动续期、私钥权限、原子部署及Nginx重载；主站配置变更先检查语法与TLS，不因申请失败停掉原站。容器默认拒绝其他隐藏目录。

部署脚本的来源白名单调整为明确批准的HTTPS公网IP，不开放任意源、关闭证书校验或跳过IP SAN校验。无需把Supabase登录回调随意改成所有网址；如实际采用OAuth/邮件回调，精确配置并验证目标HTTPS源。

参考：
- https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability
- https://letsencrypt.org/2026/03/11/shorter-certs-certbot

本设计只解决技术验证；IP证书不替代服务器提供商的服务规则或后续公开运营手续。
