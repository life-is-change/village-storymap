# 实景建筑近景相机设计

## 问题

点击主 Viewer 的白模建筑后，实景 Viewer 当前调用 `viewer.flyTo(透明代理建筑)`。透明代理的包围体由白模地形高度和挤出高度构成，不代表倾斜摄影网格的真实屋顶表面。Cesium 因而可能把相机目标放到实景地表、植被或网格内部，形成“贴地锁定”的画面。

用户需要的是稳定的建筑近景构图：整栋建筑居中，同时看到屋顶与立面，效果类似手动把相机调整到建筑斜上方，而不是改变建筑对应关系。

## 目标

- 保持现有建筑编码和透明代理匹配机制。
- 点击白模后，实景 Viewer 自动形成整栋建筑近景，而非飞入地表。
- 使用倾斜摄影 3D Tiles 的实际表面高度确定观察焦点。
- 根据建筑尺寸自动选择观察距离，小建筑不太远，大建筑不被裁切。
- 查询失败、浏览器不支持取高或瓦片缺失时使用安全回退视角。
- 连续快速点击建筑时，旧的异步取高结果不得覆盖较新的定位请求。

## 定位流程

### 1. 建筑几何摘要

主 Viewer 在生成实景代理记录时额外计算并传递：

- 建筑轮廓中心的经纬度位置。
- 轮廓水平包围半径。
- 白模建筑高度。
- 白模地形高度，仅作为回退值。

实景控制器保存这些摘要，不再依赖 Cesium 自动计算透明代理的包围体作为相机目标。

### 2. 实景表面取高

定位请求使用建筑中心的 `Cartographic` 坐标调用 Cesium 1.118 的 `scene.sampleHeightMostDetailed`。该 API 会按最高细节层级查询场景中的 3D Tiles 和地球表面。

取高流程：

1. 等待 Asset 5133927 tileset 完成创建。
2. 使用建筑中心经纬度请求最高细节表面高度。
3. 得到有限高度时，将其视为建筑屋顶附近高度。
4. 将观察焦点设置到屋顶以下约建筑高度的 35%，使焦点靠近建筑上部中心，便于同时看见屋顶和立面。
5. 如果取高返回 `undefined`、抛错或浏览器不支持，则使用代理的回退高度，但仍使用独立安全相机目标，不调用 `viewer.flyTo(entity)`。

### 3. 近景相机构图

相机使用人工构造的 `BoundingSphere` 和 `camera.flyToBoundingSphere`：

- 俯角：约 `-30°`（`-Math.PI / 6`）。
- 方位角：优先保留当前实景相机 heading，使连续浏览不会反复跳转方向；无有效 heading 时使用东南向默认角度。
- 包围半径：取轮廓水平半径与建筑高度的一半中的较大值，且不小于 6 米。
- 观察距离：由包围半径乘系数得到，并限制在 35–90 米。
- 焦点：实景表面取高后的建筑上部中心，而不是透明代理包围体中心。

这样小型住宅会得到与参考图相似的近景斜视构图，大体量建筑会自动拉远以保持完整。

## 并发与状态

- 继续使用现有 `createFocusRequestGate`。
- 表面取高返回后必须再次检查请求 token；如果期间点击了另一栋建筑，丢弃旧结果。
- 定位期间状态显示“正在获取实景建筑表面…”。
- 成功后显示“已定位建筑 CODE”。
- 取高失败但安全回退成功时显示“已使用近似高度定位建筑 CODE”，不显示加载错误。
- 只有相机飞行本身失败时才显示定位失败。

## 代码边界

- `app-3d.js`：计算代理记录的中心与水平半径。
- `features/3d/reality-inset.js`：保存代理摘要、取实景表面高度、计算相机参数、执行安全近景飞行。
- `features/3d/reality-inset.test.js`：测试近景相机参数、取高回退及请求竞争规则。
- `features/3d/3d-runtime-integration.test.js`：确认主 Viewer 向实景控制器传递中心和半径。

不改动 Asset ID、Cesium Token、整体模型变换、建筑编码匹配和窗口布局。

## 验证

- 单元测试验证 10 米级住宅的距离落在 35–90 米范围、俯角固定为约 30°，以及超大建筑会自动拉远但不超过 90 米。
- 单元测试验证实景取高成功时使用采样高度，失败时使用回退高度。
- 集成测试验证代理记录包含中心和水平半径。
- 浏览器测试加载真实 Asset 5133927，点击代理后确认相机高度高于目标、与目标保持安全距离，并且状态不再停留在地表。
- 人工视觉检查整栋建筑同时显示屋顶与立面，且不会出现相机嵌入绿色网格的画面。
