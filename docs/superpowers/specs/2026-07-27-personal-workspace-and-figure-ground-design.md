# 个人空间隔离与图底关系合成设计

## 目标

让每位学生只看到自己的个人图底空间；删除旧空间后不会被浏览器缓存重新写回；图层开关不再触发整图重建和无关的网络请求；并将图底关系作为始终反映当前个人图层的实时组合视图。

## 现状问题与根因

`planning_spaces` 同时承担了旧版全局空间、课程小组空间和浏览器同步目标三种职责。旧版 RLS 的 `Allow all` 策略允许任意登录用户读取历史空间；前端又会把本地残留列表整体 upsert 回该表。因此删除的空间会被另一台含旧缓存的浏览器重新写入。

个人图底空间存放在 `course_personal_spaces`，但旧版同步逻辑会用远程 `planning_spaces` 覆盖本地列表，导致刚创建的个人空间消失。

图层切换会重建完整的 OpenLayers `VectorSource`，逐一转换全部 GeoJSON 要素，并强制刷新社区任务数据。这使得小型 GeoJSON 文件也会因要素构建、样式计算、数据库请求及并发刷新而卡顿。

当前“图底关系”只是临时渲染模式，没有保存任何明确的合成版本或所引用的四类图层版本。

## 数据边界

| 数据 | 唯一用途 | 客户端处理原则 |
| --- | --- | --- |
| `course_personal_spaces` 与个人图层版本表 | 学生个人图底成果 | 个人空间是学生端唯一的成果空间来源。 |
| `planning_spaces` | 教师或课程小组的协作空间 | 学生不能读取无关历史空间；个人空间绝不写入此表。 |
| `localStorage` | 账号级界面偏好和短期离线回退 | 不作为远程空间的写回来源。远端空列表必须覆盖旧的本地规划空间。 |
| 图底关系图层 | 个人图层的组合显示 | 始终读取建筑、道路、水体、等高线的当前版本；不复制、不熔合、不额外创建版本。 |

## 个人空间同步

1. 登录并进入课程时，通过 `ensure_course_personal_space` 确保该账号、课程和村庄唯一的个人空间存在。
2. 个人空间加入浏览器的空间选择列表，但不调用旧的 `planning_spaces` 写入逻辑。
3. 从 `planning_spaces` 同步结果时，保留现状空间和个人空间；学生仅接受自身当前小组的课程空间。
4. Supabase RLS 限制 `planning_spaces`：教师/管理员可管理，小组成员只能访问本组的 `course_group` 行；匿名用户无权访问。
5. 浏览器加载到合法的空远程结果时，移除旧的本地规划空间，避免“删掉又回来”。

## 图层性能设计

地图保留已加载的矢量数据，并按图层维护独立的显示源或可见性状态。点击建筑、道路、水体、等高线或图底关系时只更新受影响图层，不重建整个地图源。

刷新请求采用“最新状态获胜”的串行机制：同一时刻只允许一个刷新过程提交地图结果；后续点击只让旧请求失效。社区问题标记不随普通图层开关强制联网刷新，而在进入相关功能或明确刷新时更新。

## 实时图底关系图层

图底关系不是需要学生反复保存的快照版本，而是个人空间四类当前图层的实时组合：`building`、`road`、`water`、`contours`。它不复制几何要素、不另建图层版本，也不会因学生一次编辑而产生 V1、V2 等版本负担。

地图选择图底关系时，读取上述四类当前版本，并用既有样式渲染：建筑黑色、道路灰色、水体蓝色、等高线沿用现有样式和数值开关。学生成功保存任意单图层修改、切换当前版本或导入新的识别结果后，图底关系自动做轻量刷新并反映最新结果。

右下角刷新按钮保留为手动兜底：它只失效当前个人空间的图层版本缓存，并重新读取该个人空间的四类当前图层。它不得同步或写回全局 `planning_spaces`，不得清空静态教师数据，也不得强制刷新社区任务与留言。

## 失败处理

个人空间或版本服务不可用时，页面显示明确错误，不回退到其他学生或历史 `planning_spaces`。图层读取失败时保留当前可见画面并显示失败状态，不清空所有地图要素。

## 验收标准

- 新注册学生只看到现状空间和自己的个人空间，不能看到他人或历史空间。
- 管理员删除遗留空间后，刷新或另一账号访问不会使其重新出现。
- 个人空间在远程规划空间为空、加载失败或实时同步后仍保留。
- 连续开关图层不会并发提交多个完整地图重建，也不触发社区任务的强制网络请求。
- 图底关系始终使用四类当前图层版本和现有视觉样式；任一图层保存后自动更新，右下角按钮可手动强制刷新当前个人图层。
