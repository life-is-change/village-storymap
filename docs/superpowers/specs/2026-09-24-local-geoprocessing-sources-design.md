# 学生个人底图生产使用 4090 本地数据：设计规格

日期：2026-09-24

## 目标与边界

管理员上传已经制作完成的数据包，仅用于共享现状空间的底图。学生在个人空间绘制研究范围后，网页只向 Supabase 提交任务参数；4090 Worker 从预先部署在本机的原始数据中读取村庄遥感影像，以及可跨广东村庄共用的 DEM、OSM 和建筑识别模型。Worker 将处理成果上传 Supabase，由网页预览或导入学生个人空间。不得因为某村没有共享数据包而阻止学生生产，也不得把管理员上传的成果反过来当作 Worker 输入。

米埗村已有本地原始数据；红星村目前缺少本地遥感影像，应显示“原始影像未就绪”并禁止新任务入队，不能把缺失误报为范围无效或项目不匹配。未来新增村庄只需登记村庄 ID/范围并在 4090 配置遥感文件，复用省级 DEM、OSM。现有共享空间展示及管理员上传流程不在本次改动范围内。

## 已确认的旧流程问题

1. `resolve_dataset` 只在米埗村且 `dataset_id` 为空时走本地目录；其余任务走 `RemoteDatasetResolver`，按任务重复下载 Supabase 的数据包。当前浏览器会随教学项目提交 `dataset_id`。
2. Supabase 的七参数提交 RPC 把 `village_datasets.layer_manifest.worker_manifest` 当必需条件，并把 `dataset_id`、`input_manifest` 写入任务。这把共享数据包与学生生产错误地耦合。
3. 本地 `villages.yaml` 仅登记米埗村；目录加载时任一文件缺失会使整个 Worker 启动失败，因此不能简单登记尚缺影像的红星村。
4. `PROJECT_VILLAGE_MISMATCH` 是提交阶段的项目/村庄资格校验，不是影像缺失；`AOI_TOO_LARGE` 是面积规则；处理阶段的 TLS 握手超时另属运行环境问题。这些错误需要分别诊断与呈现。

## 方案选择

采用“Worker 本地源数据目录 + 云端就绪状态”方案。替代方案一是继续从共享数据包下载输入，但违背数据位置和双流程要求，且引入重复传输。替代方案二是仅在 Worker 领取后报告缺失，虽然改动较少，却会让学生长时间排队后才知道红星村不可处理。就绪状态只发布可用与否及缺失类型，不公开本地路径。

## 数据契约与组件

- 本地配置以 Supabase 村庄 UUID 为主键；旧 `mibu` 任务兼容映射到米埗村同一组源数据。村庄条目配置遥感影像和覆盖范围；省级条目配置 DEM、OSM、模型及来源元数据。所有路径必须限制在 `PLATFORM_DATA_ROOT` 下。配置可以包含未就绪村庄；Worker 启动时不因单村文件缺失退出，但共享文件/配置语法错误应明确报警。
- Worker 在启动及定时心跳时验证每村需要的文件存在、可读且范围元数据有效，向 Supabase 发布村庄源数据就绪状态与检查时间。状态按时间失效；Worker 离线或状态过期时不得显示“可处理”。只发布错误代码，不发布绝对路径、密钥或文件内容。
- 新提交 RPC 根据教学项目和当前用户确认该村可选，再检查新鲜的本地源数据就绪状态，最后校验 AOI 与面积并入队。任务只保存村庄 ID、AOI、处理步骤、参数和个人空间所需上下文；新任务的 `dataset_id` / `input_manifest` 为空。保留旧任务字段用于读取历史记录，不再作为新任务输入依据。服务端校验仍是最终权威，浏览器状态仅用于即时反馈。
- Worker 领取任务后只根据村庄 ID 查找本地目录。即使历史任务带有 `dataset_id`，也不得因该字段切到远程下载。启动、提交和实际处理时均检查数据；文件在排队后被移走时返回明确的 `LOCAL_SOURCE_NOT_READY`，不无限重试。
- 页面在绘制前切到对应个人空间，展示该村“就绪/缺少原始影像/Worker 离线”状态。提交按钮与后端校验一致；缺源数据、项目无权、AOI 超范围分别给出不同提示。共享现状空间的图层和管理员上传功能不受此状态影响。

## 范围、性能与失败处理

数据库中的村庄边界、4090 影像可用范围和任务面积上限是三个不同约束。前后端使用同一任务面积上限；AOI 必须属于当前村且位于可处理影像内。不要用“村庄总面积”隐式代替单次任务面积上限，也不要因缩小地图视图而改变已绘制 AOI。每次失败显示具体校验代码及可执行建议。

记录排队耗时、源数据检查、裁切、建筑识别、OSM、等高线和结果上传各阶段耗时。切回本地数据可消除每任务下载，但 10 秒完成仅作为性能对比目标，不作为未经测量的保证。任务去重/并发限制保留，避免重复点击造成假性排队。

## 验证与发布

先做单元与契约测试：本地目录解析、村庄 UUID 映射、缺影像不影响其他村启动、过期就绪状态拒绝提交、项目/村庄资格、AOI 面积和边界、只读本地输入、不产生远程下载、任务结果导入个人空间。再在测试环境验证米埗村完整闭环，以及红星村缺影像时即时、清晰拒绝；补齐红星村影像后再次验证闭环。保留历史任务和共享空间图层。数据库迁移先于新前端/Worker 部署，并安排可回退版本；实际 Supabase 执行和 4090 文件部署须在具备相应访问权限时单独验收。
