# 真实三维村庄中的早市示范：设计稿

日期：2026-11-01。状态：供用户确认，尚未开始产品实现。

## 1. 目标与已确认选择

老师希望先把菜市场这一处场所做细，形成可观看、可修改并能启发学生的动态生活示范。用户确认：先做一次早市，优先直接置于现有三维村庄，而非切换到独立近景。

必须连贯呈现：摊主进入市场并摆摊 → 村民进入 → 与摊主交流 → 买菜 → 村民离开。自由逛摊、讲价及摊主陆续离开不是用户强制要求；本稿建议保留简单的错峰到场与收摊，让一场早市有开始和结束。

### 考虑过的方式

- 已选：现有 Cesium 村庄中放置可编辑的市场预设，拉近即可观察。人物与村庄道路、场景方案保持连续；需要补齐市场内部导航及摊位行为。
- 未选：切换到单独制作的市场近景。细节容易集中打磨，但会增加两套空间中的人物、时钟与状态同步，也削弱学生修改真实空间后的直接反馈。

本次为一项完整功能，按“先打通行为闭环，再打磨同一市场的可见细节”分段交付，不同时扩展其他场所。

## 2. 当前代码与约束

- 场景工作室以 SceneDocument 保存 EPSG:4326 几何、组件和方案差异，基线只读；已有面域、路径和 seed:stall:market 市集摊位。
- village_game/domain/life.js、schedule.js 提供固定身份、岗位、沿路行走和日程。普通购物时段目前主要在下午，不能直接改名当早市。
- stories.js 目前主要面向休憩与公共活动中的短事件，不提供工作摊主与买菜顾客的交易流程。
- integration/overlay.js 共用 Cesium Viewer，人物使用原创像素角色；室内活动目前简化为场所标记。要显示市场内移动，必须提供真实的内部位置，不能把入口标记当室内导航。
- 最近线上验收记录存在“源对象编号重复：baseline:building:2:0”。实现前先复现并解决真实原因，保留不同源要素及已有方案引用；不能通过删除现状建筑或随机改号来绕过。
- 按项目规则在原目录 main 工作，保留已有无关未提交内容；不另建工作树。实施前再次核对目录、分支及状态。

## 3. 第一版场景与默认教学情境（以下为建议默认值）

采用露天或开敞棚下的早市，避免屋顶完全遮挡人物。提供一套约 24×18 米、6 个摊位的预设：4 个蔬菜摊、1 个水果摊、1 个豆制品/干货摊，包含货筐、摊台、棚架、招牌、主通道和出入口。确切尺寸和美术组合由实施者在占地与性能验证中调整。

用户先选择或划定场地，再预览、确认放置整套预设。系统不自行占用一块真实村庄用地。预设超出场地、与现状建筑冲突或通道不通时提示原因，不自动移动或删除现状。放置为一个可撤销操作，之后可单独编辑摊位位置和朝向。

市场是一个父设施；内部摊位是带稳定 ID 的子组件，不同时算成多处独立生活商店。装饰组件不重复产生岗位或客流。

首次提供明确标注的“早市教学情境”，建议 6 名摊主、12 名买菜居民、1 场早市。人物采用合成身份与家庭，不声称来自真实调查。角色来自本轮统一人口池，在村路和市场内保持同一 ID；同一人不能兼任同时发生的摊主工作与顾客购物。示范预设须提供足够的成年/老年居民与住宅，不能要求用户逐个人排班；自定义方案不足时明确提示，不暗中增添展示人群。

## 4. 一场早市的节奏

建议观察窗口 06:00—10:00，可在配置中调整：

1. 06:00—06:30：摊主错峰从各自住宅出发，沿可达村路进市场，再走到所属摊位后方。到岗后依次摆出货筐、货品、招牌，进入营业状态。
2. 06:30—09:30：买菜居民分批从家中出发，走村路、穿过入口，再沿内部通道到某个可营业摊位前。人数不是从入口凭空刷新。
3. 每笔购买：走到摊前 → 必要时排队 → 转向摊主、交流 → 摊主取货/递交 → 顾客获得菜袋 → 离开服务位置。第一版每位顾客完成一次购买即可回家；预留日后增加多摊采购的能力。
4. 09:30：不再开始新的进场购物任务；已进入市场的排队和交易按规则完成或得到明确的未购买原因。不能让顾客永远等待。
5. 09:30—10:00：没有待服务顾客的摊主陆续收起货品并离场，沿原有可达路线返家。到结束时仍未完成的活动有明确记录。

这些时间、队列距离和服务时长均为可调整的教学参数，不作为现实市场预测或设计规范。

演示与全村共用一个模拟时钟。10:00 自动暂停并显示早市局部摘要，不把四小时的局部过程冒充为完整一天的村庄结算。全日模拟继续使用现有流程；早市示范通过明确的角色/日程情境启用，不全局改写普通商店的日程。

## 5. 行为规则与交流

### 摊位状态

未到岗 → 摆摊中 → 营业中 → 收摊中 → 已离场。仅“营业中”可以开始交易；到达截止时不打断已经开始的服务。每摊第一版同时服务 1 人，有有限队列，队列满时顾客可选其他可营业摊位或记录未购买并离开。

### 顾客状态

出发 → 村路行走 → 市场内行走 → 等候 → 交流 → 接货 → 携菜离场 → 返家。摊主缺席、道路不通、入口未连接、全部摊位忙或营业结束，必须产生等待、改选或未购买结果，不能直接记为购买成功。

### 对话与动作

先用身份与活动驱动的短对话，不接入大模型或语音服务。对话绑定实际顾客、摊主、摊位和交易 ID，例如招呼、询问菜品、回应和致谢；展示双方姓名、说话次序及气泡。第一版不实现复杂讲价。

优先表现：摊主摆货、面对顾客、取货递交；村民停步、面向摊主、接货及提菜离开。复用原创角色并增加相应姿态/道具，不以文字气泡代替全部动作。不宣称已有精细骨骼动画。

交易成功只记录可核验的购买事件与携菜状态；第一版不做真实支付、货币、复杂库存、定价经济或收入模型。显示的货品变化属于演示状态，并与交易/收摊对应。

## 6. 内外导航和三维呈现

村庄道路接到市场入口；内部有独立的可步行通道图，连接入口、摊主站位、顾客服务位、排队位和出口。入口负责村路与场内路径交接，不生成第二个人物，也不把人瞬移到摊前。

内部路径必须留在父场地内，并避开摊台、组件及其他不可穿越对象。市场父面域作为可进入的场所，不因自身轮廓被当成封死内部的障碍；其他现状建筑仍阻挡通行。内部排队位置不能占到货摊中。首版不做物理级人群推挤或密集避碰，采用错峰到达、稳定排队位和适当间距。

统一使用现有地理坐标/米制投影与同一 Cesium Viewer。场内人物、组件共用一致的地面高度策略，避免摊位贴地而人物漂浮。先检查场地坡度；不为演示修改真实地形。首版不做楼层、封闭室内或台阶级导航，坡度或净空不适合时提示换位/调整。

提供“观察早市”定位，把相机拉到市场近景，之后保留用户自由平移、旋转与缩放。点击人物可跟随，取消后恢复自由观察；摆摊、购买或收摊事件不自动反复抢镜头。远景简化标签，近景看清摊位和人物；只为正在交流的少数人物展示气泡，避免满屏文字。

## 7. 编辑、保存和重放

- 场地与内部组件仍保存于同一 SceneDocument，新增市场用途、归属和角色/时间配置；具体字段设计由实施者确定，但不新增第二份市场几何真源。
- 运行时由冻结的方案几何和早市配置生成内部路径/服务位。配置与早市摘要接入现有 metadata.simulation、保存/冲突处理、来源摘要和权限体系。
- 运行时不把摆货、行走或菜袋姿态逐帧写回场景文档，不污染用户设计和现状。
- 规则版本、预设版本、随机种子、市场/摊位稳定 ID、角色分配进入运行输入标识；相同输入按同一时钟重放。暂停、调速不能改变交易次数或凭空补人，重新开始清理旧角色、队列和事件。
- 更新市场布局后重新检查内部通路与服务位。缩小范围导致子组件越界时保留配置并提示修正，不悄悄删对象。
- 学生仍使用小组方案；管理员仍使用隔离的试用方案。不开新权限，不写共享基线，不调用 4090，不引入额外付费服务。

## 8. 演示操作与摘要

用户路径：选场地/放置早市预设 → 核对入口接路 → 选择早市教学情境 → 检查并保存 → 播放 → 拉近观察人物与摊位 → 查看散场摘要。

界面至少能识别当前阶段、营业摊位数、场内顾客数、排队人数和完成购买数；选择某人可看到“去哪个摊位/正在与谁交流/已购买/未购买原因”。无需逐个人手工调度。

结束摘要包括到岗摊主、进场顾客、成功购买、未购买原因、平均/最长等待、主要通道使用情况及已完成交流数。交流次数不等同于社会资本或市场真实经营成效。第一版保留这些观察依据，不把全村规划评价系统扩进来。

## 9. 分段实现与验收

1. 前置：复现并回归修复源编号重复；确认主平台模拟能够打开、保存和启动。
2. 行为闭环：在真实村庄放入一套预设，至少 2 摊主、4 顾客完整走过“从家出发—摆摊/交流买菜—离场返家”，先验证身份、路径、时钟与交易正确。
3. 完善同一早市：扩充到建议的 6 摊主、12 顾客，完善货品、姿态、气泡、排队和错峰散场，达到可以给老师/学生观看的程度。第 2 步只是内部检查点，不作为完成整项需求的交付。

必要验证：

- 不可达/未到岗/未营业/队列满/关闭时段均不误报成功；一位顾客的一笔交易只记一次，摊主不同时服务多人。
- 同一输入重放一致，暂停/调速不重复交易；旧快照/异步回调不能污染新运行。
- 内外位置连续，人物无穿摊、越界或入口叠成一团，携菜动作发生于成功购买之后。
- 场景保存、重新打开、撤销预设放置、既有方案和非早市场景保持兼容。
- 米埗村与深井村均需用实际当前基线做完整浏览器验收；至少一轮保存后刷新重开验证。部署前明确记录测试方案身份，避免覆盖真实小组成果。
- 核对原有三维首屏不再出现全球视角闪黑/二次抢镜头回归。检查既有静态场景按需渲染仍生效，早市暂停后无持续无意义重绘。
- 在同一设备/视口记录运行帧率与对象数；避免每人重复创建纹理/模型，每帧重复查询地面；远景限制气泡和标签。性能不足时优化共享资产与更新频率，不暗中减少实际模拟人数来冒充已达到默认规模。
