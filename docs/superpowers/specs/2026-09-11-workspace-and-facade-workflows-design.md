# 工作区协调与立面生成工作流设计

## 背景与目标

平台当前在左右侧栏同时展开时，顶部工作区控件会因可用宽度不足而重叠；几何校核面板只有“确认几何无误”，不能快速进入当前对象的矢量编辑；3D 操作提示会被左侧任务轨道遮挡。乡村建筑 3D 生成器仍保留不再需要的预设样式资源，同时本地自动处理、外部 AI 辅助和未来云端 API 处理没有形成清晰、可扩展的三种工作流。

本次改造目标是：让工作区控件在任意侧栏状态下保持单行、可读和可操作；建立从几何校核到当前对象编辑的直接入口；修正 3D 提示遮挡；彻底移除预设样式；将建筑实拍图处理整理为三种相互独立但共享后续建模步骤的入口。

## 设计原则

- 顶部控件按中央工作区的实际宽度响应，不按浏览器视口猜测可用空间。
- 响应式降级先隐藏重复说明文字，再缩短控件，最后隐藏低优先级标签；关键操作不得换行、重叠或消失。
- “编辑几何”是当前对象的快捷操作，不要求用户再次在地图上寻找同一对象。
- 云端模型密钥不得进入静态页面、查询参数、浏览器存储或客户端日志。
- 三种立面处理方式只负责取得标准正立面；裁屋顶、生成 GLB、下载和替换建筑继续复用同一后续流程。
- 移除预设样式时同时删除代码、界面、测试假设和版本库资源，不保留不可达的兼容分支。

## 1. 顶部工作区布局

### 布局依据

`.center-panel` 继续作为 CSS 容器。顶部栏根据中央工作区容器宽度及左右栏状态切换布局密度，保持固定单行高度，不使用换行来掩盖空间不足。

### 显示优先级

1. 始终保留：首页、村庄选择、空间选择、2D/3D 切换、现状进度/标记入口。
2. 中等宽度时隐藏工作区身份块，因为展开的左侧课程面板已经提供相同信息。
3. 更窄时将班级讨论和图层设置收缩为带 `title` 与无障碍名称的图标按钮。
4. 管理村庄不显示课程相关动作时，网格轨道必须随实际 DOM 数量减少，不能留下空轨道。

顶部栏的所有网格子项都设置 `min-width: 0`，下拉框文字使用省略号；进度控件内部不得覆盖相邻图标。

## 2. 当前对象“编辑几何”快捷入口

### 界面

在对象几何状态卡底部提供并列操作：

- 待校核对象显示“确认几何无误”和“编辑几何”。
- 已确认或已修改对象仍显示“编辑几何”，方便继续修正。
- 删除对象等不可编辑状态不显示快捷编辑。

按钮保持次要视觉权重，避免压过对象状态。

### 行为

点击“编辑几何”后：

1. 校验当前空间、当前角色和对象图层是否允许编辑。
2. 展开左侧课程任务面板并切换到矢量编辑任务。
3. 激活与当前对象一致的建筑、道路或水体图层。
4. 以当前已选对象为目标进入顶点编辑并获取既有编辑锁；不能获取锁时保留对象选择并显示占用者信息。
5. 编辑、保存和版本记录继续走现有几何编辑器与共享现状校核流程。

快捷入口不得复制一套新的保存逻辑。

## 3. 3D 操作提示

`#model3dHint` 的安全左边距由当前可见遮挡组成：常驻任务轨道加已展开的左侧课程面板，再加地图内边距。侧栏状态改变时只通过共享 CSS 变量更新位置，不在 JavaScript 中写像素值。

提示保持在 3D 画面底部，不遮挡测量、复位等右侧地图控件；小屏下允许限制最大宽度并省略次要文字，但不得裁掉开头。

## 4. 移除预设样式

删除以下内容：

- 生成器中的“预设样式”模式、样式列表、搜索和预设专用字段。
- `rural_house_generator/building_styles/` 下的 28 张图片。
- 仅服务于预设样式的 `rural_house_generator/normalization_meta.json`。
- `app.js` 中加载元数据、选择预设、按预设图片拆分四面纹理及生成预设建筑的代码。
- `style.css` 中只服务于预设列表和双模式切换的规则。

建筑长度和宽度继续由当前地图对象参数或人工输入提供。楼层、层高等与实拍图工作流无关的预设字段删除；实拍立面的建筑高度继续按裁剪后比例计算。

## 5. 三种标准正立面获取方式

生成器默认展示三种方式卡片，并记录当前选择的 `facadeSource`：

### `local_worker`：工作站自动处理

沿用现有 Supabase 队列、4090 worker 心跳、任务恢复、裁屋顶和 GLB 产物流程。工作站离线时明确提示可改用外部 AI 或云端 API，不把网络故障描述成本地页面故障。

### `external_prompt`：外部 AI 辅助

提供：

- 可复制的标准正立面提示词。
- “打开豆包”外部链接。
- 上传 AI 处理结果的入口。

学生将原照片交给外部 AI 后，把返回图上传平台；上传结果仍登记到当前建筑照片素材库并记录上传者。后续裁屋顶、生成模型和替换原建筑与自动流程一致。

### `cloud_api`：云端 API 自动处理

客户端只调用平台自有的服务端端点。服务端采用 provider adapter：

```text
submit(inputPhoto, prompt, options) -> providerJobId
poll(providerJobId) -> queued | running | succeeded | failed
fetchResult(providerJobId) -> image bytes + mime type
```

首个适配器为阿里云百炼千问图像编辑；配置项只从服务端环境读取：provider、API key、模型、输出分辨率、超时、最大重试次数和单任务预算上限。未配置时，能力探测返回 `available: false`，界面显示“管理员尚未启用”，不能出现空白按钮或前端异常。

云端生成结果必须下载并保存到平台控制的存储中，不能长期依赖模型服务提供的临时 URL。成功结果作为标准正立面进入现有裁屋顶与建模流程，并在任务记录中保存 provider、model、尝试次数和估算费用，不保存 API key。

## 费用与默认控制

千问图像编辑按成功输出计费。本设计默认使用价格较低的图像编辑模型，并在服务端限制每个任务的成功输出次数；界面在重新生成前提示会产生新的调用费用。管理员可关闭云端入口或设置课程级预算。

Kimi 当前作为图像理解与文字/JSON 输出服务，不作为正立面图片生成 provider。其体验额度不改变这一技术边界。

## 错误处理与降级

- 任一方式失败时保留原始上传照片，不自动删除素材。
- 本地工作站离线、云端未配置、云端余额不足、限流、内容审核失败和超时使用不同中文提示。
- 云端请求采用有上限的重试，不对明确的余额不足、鉴权失败或内容审核错误重试。
- 外部 AI 模式不声称平台能够观察豆包生成进度，只在用户上传结果后继续。
- 切换处理方式不会清除当前照片；真正提交前再次确认所选来源。

## 测试与验收

- 静态布局测试覆盖左右栏四种组合，并验证顶部栏每个可见控件有独立轨道或可控收缩规则。
- 浏览器尺寸回归覆盖两侧展开、仅左侧展开、仅右侧展开和两侧收起，顶部栏不得重叠或换行。
- 几何面板测试覆盖不同状态下按钮可见性、当前对象直达编辑、权限拒绝与锁冲突。
- 3D 提示测试验证左侧轨道和课程面板展开时的安全偏移。
- 生成器测试验证版本库不再引用预设图片或 `normalization_meta.json`。
- 三种来源分别测试：本地队列成功/离线恢复，外部结果回传，云端未配置/成功/失败/限流。
- 云端密钥扫描验证客户端构建产物、HTML、日志和数据库行均不包含密钥。

## 非目标

- 本次不为 Kimi 编写图片生成适配器。
- 本次不在浏览器中直接调用千问 API。
- 本次不改变现有照片“本人或管理员可删除”的权限规则。
- 本次不重新设计 GLB 几何生成、屋顶分析或建筑替换协议。
