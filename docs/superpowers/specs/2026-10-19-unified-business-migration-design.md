# 普通业务统一接入与集中交付设计

状态：2026-10-19 用户已审阅确认本文，并补充采用双站点独立业务库：阿里云网站连接阿里云业务数据库，GitHub Pages 保留 Supabase 业务连接。本文已按该明确要求修订；尚未实现统一 API、统一候选页面或正式切换。

本文件细化已批准的 [混合数据库设计](2026-10-15-hybrid-database-migration-design.md)，延续其权限、数据一致性和回退约束。原设计中停止旧站写入、镜像覆盖原业务表及源站整体让位于阿里云的描述，由用户最新的双站点独立运行要求取代，以本文第1/3/7/10节为准。A/B/C2a 的既有云端证明继续有效；仅对受后续改动影响的内容回归，不再要求用户重复执行每个旧阶段。

## 1. 目标与交付方式

用户希望阿里云站点普通平台功能访问广州本地数据库，GitHub Pages 站点继续访问 Supabase，保留 Supabase 的认证及 4090 通道；减少手动上传镜像、反复输入密码和执行分散命令的次数。目标是交付一个可完整操作的候选版本，而非继续交付相互分离的内部接口。

两个站点从初始化快照之后独立写入普通业务，不提供自动双向同步或跨站实时通知。源站仍是可用平台，不再只是只读备份；本地角色、成员和照片变更不能覆盖源站对应记录。共享 Auth 仍意味着两个站点使用同一认证 UUID/密码，源 Auth 的全局密码修改或停用会同时影响两边；阿里云的业务停用/成员撤销只改变本地权限，不隐式全局停用 Auth 用户。

本轮包含剩余普通业务接口、真实页面接入、任务必要衔接、自动验收与统一部署工具。代码仍在原项目 main 开发，测试后提交并推送 GitHub；用户只负责一次候选部署、少量真实页面操作，以及之后明确的正式交接操作。

采用“一个统一候选交付，独立正式交接”。另两种方式不采用：继续把接口拆成多次用户部署会增加操作成本；直接把全部线上读写切到旧副本会丢失快照之后的业务更新。

集中交付不取消内部增量开发、测试或检查点。实现可分多个本地提交；不把每个提交变成用户部署任务。

## 2. 已有证据与限制

- 原网站已在阿里云运行，但正式数据请求仍访问 Supabase。
- 2026-10-15 数据归档已恢复并核对：106 张含数据的表、14 个序列、4 个认证用户、137 条文件元数据。
- 23 个普通文件、7,271,979 字节已复制并授权读回；114 个 GPU 产物保留源端。
- C2a 在云端版本 `66b8110` 通过真实管理员/成员、文件上传、场景保存、版本及 API 重启验证；3 个合成文件共540字节。此证明不是全部真实页面验收。
- 主机实际内存约1.6GiB，最近 available770MiB；这是空闲采样，不能推出班级并发容量。
- 公网目前仅 HTTP/IP，无可用域名/HTTPS。实现和本地候选测试可先完成；公网认证业务接入必须具备 HTTPS。
- `business-api/src/auth.mjs` 每次请求在线调用 Supabase Auth。数据库本地化仍保留该网络往返；本轮测量时必须把身份验证、数据库和文件耗时分开。

## 3. 一个候选 API 和一个业务主库

统一候选使用既有单 PostgreSQL 实例中的新业务候选库、独立最小权限登录角色和私有文件目录。恢复基线、C1、C2a 及其文件与证明不覆盖。统一 API 复用已验证的场景和文件服务，新增普通业务模块，统一路由和错误契约；不再为每个模块常驻一个新 API 容器。

普通页面只选择整套 source 或 candidate/aliyun 业务客户端。GitHub Pages 发布始终使用 source；阿里云构建显式产生 candidate/aliyun 配置，不能将该配置提交为仓库全局默认值。配置由部署产生，不以 URL 任意参数或 localStorage 选择远程 API；不实现通用 Supabase 查询模拟器，不接受任意表名、函数名、SQL、远程 URL 或任意文件路径。

候选配置中未支持的操作明确失败。不能在失败时向 Supabase 重试写入、返回空列表伪装成功，或将旧本地缓存作为已保存结果。草稿和缓存包含环境、用户 UUID、项目/村庄/空间标识；不会混用正式草稿。

源 Auth SDK 保留登录、刷新和会话功能；业务模块通过显式适配器访问同源 API。默认正式配置维持 source，阿里云候选/正式配置与对应静态资源成套发布。部署产物记录站点实例ID、Git提交、schema版本、镜像摘要、数据库和文件清单摘要，防止新页面连接不兼容旧 API。发布测试同时验证两种配置；阿里云部署不能修改 GitHub Pages 的发布产物或源端普通业务授权。

## 5. 服务接口、权限和身份

使用 `/api/v1` 下的固定域路由：`/me`、`/bootstrap`、`/courses`、`/spaces`、`/survey`、`/planning`、`/personal`、`/models`、`/scene-files`、`/admin`、`/community`、`/mc`、`/events`、`/tasks`。路径内动作仅来自服务端常量清单，每个动作单独校验方法、字段、上下文、尺寸、权限和响应字段。前端不能指定后端函数名；未识别字段/动作拒绝。

本地业务角色使用服务端验证的 UUID，通过事务内身份上下文执行 RLS 或经审查的窄接口。表级 grant 不扩大成所有 authenticated 可任意写入。每条池连接结束前事务完成/回滚，异常连接丢弃；DDL、恢复和管理凭据不进入 API 运行时。

本轮身份验证保持已有源端在线确认，不为了宣称“全本地”而只解析 JWT。登录资料与初始化数据提供有界聚合请求减少 N+1。注册首次就绪从可信服务端认证资料建立默认 student 档案；既有档案不由 user_metadata 覆盖角色、成员关系或停用状态，角色提升只由本地授权管理操作执行。资料同步失败明确显示未就绪并可幂等重试。

教师/管理员由本地权限决定；账号停用、撤销、组锁和空间归属每个操作检查。管理与高权限任务入口不信任显示名称、学号或浏览器缓存。源 Auth 不可用时依当前契约拒绝认证业务，不以匿名或过期身份继续保存。

## 6. 文件、场景事务与协作通知

普通文件复用 C2a 的私有目录、不可变文件、哈希、类型/尺寸、配额和路径校验，新增照片、原模型库、村庄包各自规则。数据库记录和真实文件分开核对；存储路径不能成为公开静态目录。删除先记录逻辑状态/引用检查，过期清理由受限维护过程执行；历史版本引用不能被清理。

页面里程碑改为“生成 PNG → 上传会话 → 服务端一次提交版本与预览引用”，不能沿用“拿到任意 previewPath 再单独 createVersion”的旧顺序。俯视图、组件预览同理。Blob URL 在替换、切换场景、退出及登出时回收；用户取消上传不会伪装成保存失败或留下可见半成品。

通知采用同源受限 SSE，浏览器通过带认证的 fetch 流读取。每个连接/重连及持续连接定期复核当前本地权限；到期或撤销即结束。事件只携带授权上下文内的失效提示与游标，不广播业务整行或令牌。事务提交后再发提示，断线/重连完整刷新，清楚显示连接状态。

事件丢失不能破坏正确性：锁仍由数据库90秒租约及原子续期/释放保证，revision冲突仍由数据库检测；页面失联不能继续报告在线锁有效。用服务器事件日志与有界重放支持重连，保留期限之外执行全量刷新。候选前端移除普通业务 Supabase channel，GPU 通知按第7节处理。

## 7. 双站点共用4090通道的隔离

保持现有 Worker 的连出方式、任务 ID、心跳和产物位置，队列变更仅作兼容扩展。历史队列副本不能启动消费者，也不直接作为本地“新任务”。服务器不是主动穿透校园内网；Worker 继续主动访问 Supabase 获取任务。

本地事务写任务请求/outbox及上下文版本；受限桥接程序向源端私有桥接命名空间同步必要上下文和照片输入，不覆盖源站公开业务表中的角色、成员、教学项目、照片或数据集。桥接密钥只在私有服务器凭据中，不能装进静态资源或镜像。同步失败显示 pending/failed，不能虚报已提交。

源端增加版本化桥接入口与幂等键映射。原 GitHub Pages 的普通写入与原任务入口保持可用，只能访问 source 来源任务；阿里云来源任务由新增服务端入口处理，浏览器不能绕过本地权限调用它。队列、产物和签名策略、用户可调用的任务RPC都必须区分来源，不因相同 Auth UUID 或 teacher/admin 角色而允许跨站操作。Worker仍通过已有服务端RPC消费原队列，添加来源字段不得破坏其行契约。

使用 `(instance_id, local_kind, local_id)` 映射，避免两库相同自增照片ID或同名空间发生冲突。队列中的源业务外键不能硬填阿里云对象ID：地理任务的本地项目/数据集引用放私有映射，旧可空外键保持null；村庄仅映射到实际已准备的Worker源配置，未准备时返回原有明确的不可用状态，不改写源村庄目录。立面任务使用原已支持的 `photo_id=null` 和独立 `source_photo_path`，输入文件放新增私有桶 `aliyun-task-inputs` 的实例专用前缀，不能覆盖旧对象或伪造源照片行。桥接入口在服务端校验本地授权快照、输入哈希和版本，不能通过null外键跳过本地业务权限。

代码审计发现 `server/src/village_processing/facade/gateway.py::download_photo` 目前只允许公开 `house-photos` URL，不能直接读上述私有桶。因此完整交付包含一项向后兼容 Worker 更新：仅对带受信来源字段的桥接任务，从固定私有桶取得短期授权并按10MiB上限流式读取/核对输入哈希；普通 source 任务仍用原读取流程。来源字段默认source，新增字段不改变旧行解释；不开放任意bucket/URL，也不把私有桶改为公开。生产启用桥接前必须先更新这一兼容Worker并验证其版本，更新与回退纳入最终集中操作清单。此前“完全不改Worker”的假设不适用于新私有照片；不能以暴露照片规避这项依赖。

撤销/删除带实例内版本墓碑，旧重试不得恢复已经撤销的本地授权；同步未确认时拒绝依赖它的新任务。桥接队列读取/取消及其文件读取不由源站旧角色授权。本地撤销不影响源站原任务权限；GitHub Pages 继续按其自身 Supabase 权限工作。Auth身份全局撤销仍依第1节共享身份边界。

新任务先查本地最新权限及引用，再同步并确认源端上下文/照片可读，最后取得唯一源任务 ID。提交响应丢失通过幂等键恢复同一个任务，不创建第二个任务；取消操作按该任务所属人与当前权限校验。撤销之后的新操作拒绝；既有任务状态/产物也不能由过期源镜像授权给已撤销成员。

产物来源、归属和任务状态由服务端向可信 Supabase 查询，不接受浏览器提供的任意下载 URL/任意 GeoJSON 作为已完成产物。对源端签名文件使用限定主机、类型、大小和结构检查；本地结果导入与个人版本变更在同一事务，以源任务/产物唯一键幂等。照片被活跃任务引用时保护源文件，结束后按历史保留规则处理。

内部自动测试用协议兼容的假远端验证延迟、拒绝、乱序、重试、撤销及双站点冲突，不提交真实 GPU 作业。真实 4090 冒烟验收集中进行一次，沿用已有授权账号；需要服务端密钥时只在隐藏提示中输入并私有保存。生产源端桥接SQL的实际应用留在正式交接操作中，候选部署不自动改变当前 Supabase 的权限或任务行为。该扩展必须有源站旧任务接口、文件策略和真实Worker契约的回归证明；不能为了避免改Worker而污染源站业务数据。

## 8. 资源与自动测试

统一 API 初始容器上限256MiB，总数据库连接池最多4；上传并发2、文件读取4，单文件限制沿用各业务规则，任务桥接低并发且无独立全量 Supabase 服务。SSE不得占用长期数据库连接。保持单 PG 实例及其768MiB限额，不把所有模块各建一个独立连接池。

部署前读取实际资源。available不足512MiB或文件可用空间不足2GiB时明确停止；如要停止旧验证 API 释放资源，必须在统一候选检查通过后，按记录的精确容器清单执行，并保留重新启动命令和数据卷。统一候选不自动停止正式 Nginx、共享 PG 或其他未知容器。

本机自动测试覆盖既有回归、每个固定操作的输入与权限、真实 PostgreSQL/PostGIS 事务、文件摘要与重启、两个学生之间的隔离、教师/管理员边界、锁竞争、断线重连、任务桥接和浏览器操作链。私有备份不导入合成测试库。

初始负载假设为10个同时活跃用户，并观察1/5/10/20并发档位；这不是已达标承诺。记录进程峰值/主机 available、磁盘空间、失败率、排队、Auth/SQL/文件分段及端到端P50/P95。与相同动作的源端基线比较，解释身份验证和大文件传输耗时。出现 OOM、持续排队、数据冲突漏报或权限泄漏时不通过；不能以空闲内存截图代替容量证明。实际教学规模更高时按目标人数补测。

## 9. 用户只接触集中交付入口

最终提供一个统一镜像归档及其校验清单、一个可重入部署入口。镜像中同时包含 API 与经 `stage-web.py` 筛选的静态产物；部署程序将静态产物提取至独立版本目录供 Nginx 使用，不复制整个仓库，不把 SQL、密钥和备份放进网站。这样页面与 API 天然对应同一构建版本。

用户在服务器更新同一 Git 提交、上传一次归档，执行一次候选命令；命令顺序完成校验、预检、隔离恢复/文件复制核对、部署、自动探测和结果摘要。正式版一套入口，旧阶段脚本保留作历史工具，不串行要求用户再手动运行它们。

候选探测一次提示管理员和现有学生的网站登录信息，内存内使用，不写密码到日志。自动检查角色隔离、代表性普通业务、文件、三维版本、连接重建和持久化；重复执行复用带标识的专用测试上下文，不能改原教学项目或重复创建测试组。成功输出一个总体结论与逐项摘要；失败输出安全错误码、准确步骤、保留日志位置和明确恢复动作。失败时不清空库或从头恢复。

用户的手动验收集中在实际页面：登录/切换空间，调查与照片保存，小组/个人规划，上传并放置模型，里程碑与恢复，4090任务提交和结果读取/导入。旧阶段通过项仅因共享代码变更在自动回归中复核；真实操作失败可只重试该动作。

## 10. 最新数据交接、HTTPS 与回退

公网候选/正式认证业务入口必须是有效 HTTPS；当前 HTTP IP 不开启新 API 令牌传输。域名/证书信息尚不存在，不在代码中假定已经购买或完成配置；部署命令可完成内部候选，但在公网就绪检查中准确列出缺项。HTTPS配置与服务商要求在实际部署前核实。

正式交接是初始化阿里云业务分支，不是关闭源站。保持 GitHub Pages 正常读写，获取一个时间点的最新一致数据库快照及可验证文件清单，在新候选应用；此后源站新增数据留在源站，不自动追赶到阿里云。文件复制遇到源端变化应按快照清单重取/复核或明确停止，不能将混合时点的文件伪装成一致副本。保留初始化时间、清单和恢复结果；不能覆盖旧已验证副本，也不能把2026-10-15快照当作最新数据。

在数据和权限版本核对完成后，只切换阿里云站点的普通读写、文件解析、通知及任务桥接。GitHub Pages 仍使用 source 配置，不撤销其普通写权限；阿里云新业务只写本地，每个页面只认一个业务库。两个站点独立演进，源库不自动包含新阿里云写入，阿里云也不自动包含源站初始化后的新写入；任务桥接不等于业务库同步。

阿里云站点切换前回退只撤候选路由。切换后已有新写入时，先停止阿里云站点写入并导出差异；如改回Supabase，须逐项解决源站在同一时期产生的冲突，不能直接覆盖或只改网页配置。优先回退阿里云上一版本并继续使用同一本地库。回退演练使用合成候选数据，正式操作前出具当前数据交接报告；不停止仍独立运行的 GitHub Pages。

## 11. 总体验收与真实状态

总体通过须同时具备：完整覆盖清单、同一版本的代码/镜像/SQL/页面、自动与真实页面权限/保存/文件/版本证明、可用协作通知、4090通道及幂等导入、最新交接与HTTPS检查、代表性负载数据、重启与回退证明。

实现交付与正式上线分别记录；不能把“镜像加载成功”“候选接口通过”或“历史副本已恢复”称为整个平台已迁移。任何尚未完成项都进入总体摘要，不能以继续留源端但页面未提示的方式冒充已接入。
