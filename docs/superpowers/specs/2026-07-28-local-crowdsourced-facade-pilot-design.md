# 众包照片建筑立面本地原型设计

## 目标与决策

先在当前 Windows 电脑上证明“修正后的建筑矢量体块 + 学生或村民上传的非标准照片”能够生成视觉上可接受的 GLB，再把相同处理核心迁移到 Linux RTX 4090 Worker。最终后台仍采用 Supabase 任务队列和 Linux Worker，但本设计只覆盖本地效果原型及其与现有 3D 页面之间的接口。

第一版结果采用已经确认的范围：

- 建筑几何服从选中建筑的修正矢量；独立运行时可用长宽矩形作为回退。
- 照片经人工归面和透视校正后成为真实立面纹理。
- 门窗保留在纹理中，不生成独立几何。
- 屋顶先使用平顶或坡顶的统一材质，不要求从照片恢复。
- 无照片的立面使用与已有照片颜色协调的 PBR/程序材质，不复制或臆造真实照片。

## 当前基础

工作区内的 `rural_house_generator` 是纯浏览器预设生成器：读取 `normalization_meta.json`，用 Three.js 生成规则体块和简化屋顶，在浏览器导出 GLB，并通过现有 `HOUSE_GENERATOR_MODEL_READY` 消息把二进制模型发送给 `app-3d.js`。这一消息契约必须保持兼容。

`E:/rural_house_generator-2026-0512` 作为选择性参考：可复用其 FastAPI 请求结构、透视校正、纹理准备、Blender 无界面导出、错误响应和 SAM3 provider 思路。不得整体复制其 `runtime_storage`、`outputs`、`__pycache__`、预设素材或内存 `job_store`。直接照片上传交互可参考 0509，但实现归属仍在工作区目标目录。

本机为 RTX 4060 Laptop 8GB，Blender 3.6.23 位于 `D:/Blender/blender.exe`。现有 `E:/anaconda3/envs/building_sam3` 在导入 PyTorch 时因 `shm.dll`/依赖入口点错误而不可用，因此原型使用新的隔离环境，不在原环境上叠加修补。SAM3 不得成为第一轮视觉验证的前置条件。

## 分阶段范围

### 第一轮：人工可控的效果基线

目标是隔离并验证照片纹理路线本身，不加载 SAM3。

1. 在生成器保留“预设样式”模式，并新增“真实照片”模式。
2. 真实照片模式支持一张或多张本地图片；后续接入平台时，同一输入接口也接受建筑已有照片记录。
3. 用户把照片分配给建筑轮廓上的立面 A/B/C/D；无法归面的照片可保留为“未知”或排除。
4. 用户在照片上确认四个立面角点，顺序固定为左上、右上、右下、左下。斜拍同时包含两个立面时，可将同一原图创建为两个裁剪任务。
5. 后端完成四点透视校正、边缘裁剪、分辨率归一和色彩统计。
6. Blender 根据建筑轮廓生成墙面四边形，将对应纹理贴到墙面；未分配照片的墙面使用协调材质。
7. 导出 GLB，在生成器中预览，并继续使用现有消息发送给主 3D 页面。

第一轮必须先跑通，因为它能直接回答“普通随手拍是否值得做”。如果人工角点条件下仍然出现不可接受的拉伸、比例或接缝，增加 SAM3 不会解决根本问题。

### 第二轮：SAM3 辅助自动化

在同一批验收照片上加入 SAM3，但保持人工路径始终可用。

- SAM3 负责建筑/立面、屋顶、门窗及树木、车辆、人物等遮挡区域的候选掩膜。
- SAM3 可给出候选建筑范围和角点搜索区域，但不负责判断照片对应哪一条地理立面边。
- 8GB 本机一次只处理一张图，优先混合精度和较低分析分辨率；显存不足时最多自动降级一次，然后明确回退到人工角点/遮罩。
- 状态中必须区分 `sam3`、`manual` 和 `fallback`，不能把传统图像规则结果标记成 SAM3 成功。
- 多个文字提示共用一次图像视觉特征，避免为建筑、屋顶、窗户等提示重复编码整张图片。

## 组件边界

### 生成器前端

目标目录为 `rural_house_generator`。前端负责模式选择、照片缩略图、立面归面、四角标注、参数编辑、任务状态、处理结果对照和 Three.js GLB 预览。预设模式保留，确保真实照片后端不可用时原功能仍可验证。

前端不直接执行 SAM3、OpenCV 或 Blender。它只生成明确的作业描述并调用本地 API。与主页面交互继续使用现有模型返回消息；新增的建筑上下文采用单独的 ready/context 握手，避免把较大的轮廓和照片信息塞进 URL。

### 主 3D 页面适配

`app-3d.js` 打开生成器时继续传递 `targetCode`、`targetSpace` 和 `targetName`。生成器就绪后，主页面可补发规范化的建筑轮廓、建筑高度/层数和现有照片列表。轮廓在发送前转为以建筑中心为原点的局部米制坐标。

本地第一轮允许主页面尚未提供上下文：此时使用手工长宽矩形。该回退仅用于独立调试，不作为最终众包工作流的成功标准。

### 本地 API 与作业存储

在 `rural_house_generator/backend` 建立精简 FastAPI 服务，绑定 `127.0.0.1`。最小接口为：

- `GET /health`：报告 OpenCV、Blender、SAM3 是否可用，但 SAM3 不可用不使第一轮健康检查失败。
- `POST /api/jobs`：上传照片和作业参数，返回作业 ID。
- `POST /api/jobs/{id}/prepare`：完成透视校正和纹理准备。
- `POST /api/jobs/{id}/generate`：调用 Blender 生成 GLB。
- `GET /api/jobs/{id}`：读取阶段、产物和错误信息。
- `GET /api/jobs/{id}/artifacts/{name}`：读取白名单内的预览、纹理和 GLB。

本地作业不用0512的进程内字典作为唯一状态。每个作业在忽略提交的运行目录内保存 `job.json` 和产物清单，重启后能够读取现有作业。原始照片、掩膜、生成纹理和 GLB 均不得进入 Git。

### 处理核心

处理核心拆成独立模块：

1. 输入验证：图片格式、像素、文件大小、轮廓和角点顺序。
2. 透视模块：四点变换、目标宽高估计、裁剪和调试叠加图。
3. 照片质量模块：清晰度、曝光、有效立面面积和遮挡比例。
4. 可选分割模块：统一的 `manual`、`sam3`、`fallback` provider 接口。
5. 纹理模块：每个立面独立输出纹理，计算墙面回退色，不强制制造侧后立面。
6. 几何模块：合并近共线短边为立面组，生成墙体、简化屋顶和每面独立 UV。
7. Blender 适配：只接收已验证的作业清单，无界面导出 GLB。

这些模块不得依赖 Supabase。迁移 Linux Worker 时，Worker 只需负责下载输入、调用相同处理核心、上传产物和更新队列状态。

## 数据流

1. 用户在主 3D 页面选择建筑并打开生成器。
2. 生成器读取目标编号并请求建筑上下文；独立模式则创建矩形上下文。
3. 生成器显示已有照片或接受本地补充照片。
4. 用户完成照片归面和必要的四角确认。
5. 本地 API 保存作业和原图，生成校正纹理及对照预览。
6. 用户确认纹理后生成 GLB；避免每次移动角点都启动 Blender。
7. 前端加载 GLB 预览，用户可以下载或发送到主 3D 页面。
8. 主页面继续按现有变换参数加载模型；本地原型阶段仍是运行时模型，不在本设计中新增 Supabase 持久化。

## 错误与回退

- 本地 API 不可用：真实照片模式显示连接与启动提示，预设模式保持可用。
- 照片无法解码或过小：在上传阶段拒绝，不创建半成品生成任务。
- 角点无效、自交或面积过小：保留原图和标注，要求用户重选，不调用 Blender。
- 某一立面缺照片：使用协调材质并在结果清单中标记缺失，不复制其他立面。
- SAM3 初始化或推理失败：记录真实错误；回退人工路径，不将作业整体判失败。
- Blender 超时或 GLB 不存在：作业进入失败阶段，保留已生成纹理以便单独重试建模。
- 主页面关闭或消息发送失败：GLB 仍可下载，前端明确提示重新打开主页面。

## 隐私与本地安全

- 本地 API 仅监听环回地址，不接受任意远程 URL 抓取。
- 第一轮原图只保存在本地忽略目录；删除作业时可同时清理原图和派生产物。
- 人脸和车牌脱敏不依赖 SAM3 文字提示；上线众包前另接专用检测器并保存脱敏副本。
- 任何模型权重、访问令牌和 `.env` 不进入仓库。

## 测试与验收

### 自动测试

- JavaScript：模式切换、作业参数、照片归面、角点坐标换算、ready/context 和 GLB 返回消息。
- Python：角点校验、透视结果尺寸、回退纹理、共线边合并、作业 JSON 恢复和 API 错误结构。
- Blender 冒烟测试：以最小矩形和四张测试纹理生成 GLB，验证文件存在、非空且包含墙体和材质。
- 保持现有生成器预设模式的 GLB 导出和 `postMessage` 行为不变。

### 真实照片验收集

使用 3 至 5 栋已修正矢量且照片来自真实随手拍的建筑，至少覆盖正拍、两面斜拍、树木或车辆遮挡、一般清晰度和同一建筑多张照片。0512预设图和0509已经校正的标准立面不能代替此验收集。

通过门槛为：

- 至少 4 栋能在每张照片最多一次人工角点修正后生成可加载 GLB。
- 主立面能被辨认，门窗保持竖直，不出现明显横向撕裂或跨面错贴。
- 模型水平尺寸服从输入轮廓，墙面和屋顶无肉眼可见孔洞。
- 缺照片立面呈现协调材质，并在界面中明确标记。
- 处理失败可定位到上传、校正、分割或 Blender 阶段，已经完成的纹理不丢失。

本机处理时长和显存峰值需要记录，但第一轮只作为迁移4090的基线，不设为效果验收的硬性失败条件。

## 迁移到 Linux Worker 的门槛

只有真实照片验收通过后才进入 Linux 部署。迁移时保持作业描述、产物清单和处理核心不变，把本地文件输入替换为 Supabase Storage 下载，把本地阶段状态替换为现有队列的领取、续租、完成和失败流程。TRELLIS、VGGT/COLMAP、门窗几何、真实屋顶恢复、3D Tiles 和模型长期持久化均不属于本地首版。
