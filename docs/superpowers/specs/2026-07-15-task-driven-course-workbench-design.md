# 任务驱动的课程工作台设计

> **过程文档：** 本文件仅用于记录方案讨论、实施范围与验收依据，不属于平台运行文件。

## 1. 目标与边界

将现有互动平台从“2D、3D、评论、照片、空间管理等功能并列”调整为“学生按课程任务推进”的工作台。首页保持现状，继续承担教学目的、理论学习和村庄信息展示；学生完成首页学习后进入互动平台开展实践。

本次不把平台扩展为完整教务系统，不新增通用即时聊天，也不重写现有地图引擎。现有 2D、3D、要素编辑、照片、评论和空间数据能力保留，并重新归入明确的教学阶段。

## 2. 学生端信息架构

互动平台主导航调整为：

1. **课程工作台**：展示当前课程、村庄、小组、阶段进度和“下一项任务”。
2. **我的任务**：按阶段展示任务说明、完成条件和状态。
3. **小组空间**：进入同一个规划空间，2D 和 3D 只作为视图切换。
4. **成果与版本**：保存阶段版本、查看教师反馈并提交最终成果。
5. **个人记录**：展示本人照片、评论、编辑、提交和小组贡献时间线。

学生流程固定为：

`加入小组 → 学习准备 → 调研采集 → 现状诊断 → 方案设计 → 协作评审 → 成果提交`

进入平台后默认打开课程工作台，不再默认直接进入地图。工作台始终提供一个主要动作，例如“加入小组”“继续调研”“进入方案设计”或“提交成果”。

## 3. 小组机制

- 每名学生保留独立账号，不允许多人共用账号。
- 教师或管理员预先创建小组，系统生成组码。
- 学生输入组码后自动加入；同一课程只能加入一个小组。
- 实践开始后管理员可锁定小组，学生不能自行退出或换组。
- 管理员始终可以移动、移除成员并指定组长。
- 加入、退出、转组、锁组均记录为操作事件。
- 小组创建时自动建立对应的小组规划空间。

## 4. 现有功能的归位

### 调研采集

照片上传归入调研任务。照片记录上传者、小组、任务、拍摄或上传时间、地图位置、分类、备注，并可选关联建筑或其他地图对象。

### 现状诊断

现有评论和社区问题功能归入诊断任务。学生可对地图位置、照片或规划要素提出问题、回复和验证，最终形成小组问题清单。

### 方案设计

2D 和 3D 是同一个小组规划空间的两种视图，共享图层、要素和属性数据。教师可按任务限定允许编辑的要素类型和工具，例如只开放建筑、道路和公共空间。

### 协作评审与成果提交

评论应绑定到具体任务、照片、问题、规划要素或版本。阶段完成时保存不可变的方案快照；最终提交冻结一个版本，同时保留方案说明、附件、小组成果和个人反思。

## 5. 页面组织

保留现有左右侧栏与中央地图的核心布局，但增加课程上下文：

- 顶部：返回首页、当前课程、当前村庄、小组、当前学生。
- 左侧：课程阶段、任务列表和完成状态。
- 中央：当前任务内容；方案设计阶段显示 2D/3D 工作区。
- 右侧：当前任务或选中对象的信息、评论、照片和教师反馈。
- 地图工具按任务开放，避免一次显示所有功能。

现有大型 `app.js` 不继续堆叠全部课程逻辑。新增独立的课程工作台、任务、分组、活动记录和成果模块，通过现有地图接口调用 2D/3D 能力。

## 6. 数据结构

首期新增或扩展以下实体：

- `courses`：课程及当前村庄。
- `course_stages`：课程阶段及顺序。
- `course_tasks`：任务说明、开放工具、完成条件和截止时间。
- `course_groups`：小组、组码、锁定状态和对应空间。
- `group_memberships`：学生、小组、角色、加入时间和状态。
- `task_progress`：学生或小组的任务状态、完成时间。
- `activity_events`：只追加、不覆盖的全过程行为日志。
- `workspace_versions`：阶段快照和提交版本。
- `submissions`：提交人、小组、版本、说明和状态。

现有 `planning_spaces` 增加课程、小组、所有者和空间类型关联；现有要素、照片、评论和社区问题表补充课程、小组、任务及操作者关联。

## 7. 行为记录

操作记录采用统一事件结构：

- `event_id` 与 `client_event_id`
- 服务端发生时间
- 学生、会话、课程、小组、任务和空间
- 动作类型
- 目标类型与目标 ID
- 2D/3D 视图上下文
- 变更摘要或前后差异
- 成功、失败及必要的错误信息

首期记录有研究意义的操作：登录、进入课程、加入小组、开始或完成任务、切换 2D/3D、创建或修改要素、上传照片、评论或回复、保存版本、提交成果。鼠标移动、地图连续拖动和每次键盘输入不记录，避免噪声和不必要的个人数据。

事件先生成唯一客户端 ID，再写入后端；网络失败时进入本地待发送队列，恢复连接后重试，后端通过客户端 ID 去重。业务表保存当前状态，`activity_events` 独立保存历史，两者不能互相替代。

## 8. 管理员端

管理员端增加：

- 课程与阶段任务配置
- 小组创建、组码、锁组和成员调整
- 学生与小组进度
- 学生操作时间线和小组贡献概览
- 照片、问题、评论及提交成果审核
- 按课程、学生、小组、阶段、动作和时间范围导出 CSV/JSON

研究导出使用学生内部标识，姓名和学号默认分离或去标识化，并在课程开始前说明记录目的、范围和保存期限。

## 9. 异常与权限

- 未登录不能加入小组或编辑空间。
- 未加入小组时只能查看课程说明，不能进入小组空间。
- 小组锁定后只有管理员可调整成员。
- 非小组成员不能修改该小组空间。
- 已提交版本只读，继续修改时从该版本创建新草稿。
- 上传、保存或日志写入失败时给出明确提示，并保留可重试数据。

## 10. 分期实施

### 第一阶段：建立课程主流程

- 新增课程工作台与任务式导航。
- 新增预建小组、组码加入、锁组和成员管理。
- 将现有 2D/3D 入口合并为小组空间中的视图切换。
- 建立统一活动事件记录与管理员查询入口。
- 保持现有地图编辑、照片和评论功能可用。

### 第二阶段：完善教学成果链

- 完善地图化调研照片和问题清单。
- 增加方案版本、阶段快照、成果提交和教师反馈。
- 增加个人时间线、小组贡献统计和研究数据导出。

### 第三阶段：按教学验证结果增强

- 增加同伴互评、量表、通知或离线调研能力。
- 根据真实课程使用数据决定是否对接学校教学系统。

## 11. 验收标准

- 学生登录后能明确看到所属小组、当前阶段和下一项任务。
- 学生使用个人账号进入共享小组空间，并能切换同一空间的 2D/3D 视图。
- 教师能创建小组，学生能凭组码加入，教师能锁组和调整成员。
- 要素编辑、照片、评论和成果操作均能识别真实操作者及课程上下文。
- 管理员能按学生和小组查看关键操作时间线并导出研究数据。
- 现有首页和地图核心能力不因工作台重组而退化。
