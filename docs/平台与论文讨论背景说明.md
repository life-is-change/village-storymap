# 乡村规划互动平台与论文讨论背景说明

## 使用说明

这份材料用于向其他GPT快速说明项目背景，便于继续讨论论文定位、研究框架和平台完善方向。讨论时需要严格区分三类内容：**代码和界面中已经实现的功能、已有设计但尚未充分经过课堂检验的功能、未来拟增加的功能**。不能把“平台具备某项功能”直接写成“已经产生教学效果”，也不能把AI模拟意见等同于真实村民意见。

## 一 项目现状

我正在建设一个面向乡村规划实践教学的互动式平台。平台以真实村庄为空间对象，主要供规划专业学生使用；教师负责确定课程目标、任务、分组原则和阶段节点，但不一定频繁直接操作系统；我既是平台开发者，也是主要管理员，根据与教师的沟通完成村庄配置、学生分组、共享现状冻结、功能维护和数据管理。村民现阶段不直接登录平台，地方信息主要来自学生在线下踏勘和访谈中取得的材料。

平台最初的思路，是把分散在课堂、现场调查、纸质记录、微信群、GIS、CAD和三维软件中的课程活动组织到同一环境中，使学生能够围绕同一村庄经历“课程学习—工作底图生产—现场调查—共同现状校核—小组方案设计—过程记录”的过程。原来的论文主线主要围绕参与式规划、地方知识、WebGIS、二维三维可视化以及调研、分析和设计之间的衔接。这些内容仍然重要，但与老师讨论后发现，它们作为论文主创新比较常见，难以充分体现平台目前最有时代性的特点。

目前更值得发展的方向是：**生成式AI不仅成为学生使用的工具，也改变了规划专业人员创造教学工具的方式。**我并非传统的软件开发人员，但借助大模型参与需求梳理、功能设计、代码生成、调试、测试和持续迭代，逐步形成了一个贴合具体课程的平台。因此，论文可以同时研究两个过程：一是规划领域人员如何借助大模型把教学设想转化为可运行的平台；二是这个平台如何在乡村规划课堂中组织真实任务、空间体验和学生协作。

老师还特别强调，平台不能只解决资料管理和流程衔接问题，还应考虑如何吸引学生进入规划学习、增强其沉浸感。这里的沉浸感不应只理解为画面逼真，而应包括：学生进入一个具体村庄情境，面对明确任务和现实约束，能够直接操作空间对象，看到方案变化，并比较不同选择带来的后果。

## 二 平台角色与基本流程

平台目前的角色关系是：村民在线下提供地方信息；学生是主要学习者和平台使用者；教师确定教学要求；管理员负责把教学要求落实为系统配置和阶段操作。它不是村民在线共同决策的治理平台，而是连接线下参与式调研与线上协同分析、设计的学习环境。

课程中的基本流程可以概括为：

> 教师与管理员设置课程和村庄 → 学生学习课程任务 → 学生生成个人工作底图 → 进入村庄调查并补充资料 → 全班共同校核现状 → 管理员按课程节点冻结共享现状 → 各小组从同一基线建立方案 → 在二维和三维中设计与比较 → 平台保留版本、日志和成果

这一流程中需要注意：学生未必会大量使用访谈关联、评论和问题标注功能。部分学生可能主要修改建筑矢量、上传照片并完成规定任务。因此，论文不能预设平台已经实现“调研证据持续进入设计”，而应通过日志、成果和访谈判断哪些功能真正进入了学习过程，哪些只是技术上存在但实际使用较少。

## 三 平台现有功能

下表所列内容以当前代码库和已有平台设计为依据。“已实现”表示已有相应代码、界面或数据结构，不代表已经在真实课堂中充分使用并证明有效。

| 功能层次 | 现有内容 | 在教学中的可能作用 | 当前需要核实的事项 |
| --- | --- | --- | --- |
| 用户与权限 | 登录、学生和管理员权限、课程和小组身份、不同空间的数据隔离 | 明确个人、全班共享和小组方案的边界 | 真实课堂中的账号、权限和分组操作是否顺畅 |
| 村庄与项目管理 | 多村庄和项目切换、村庄边界、数据包与预览、管理员配置 | 让不同课程或案例使用独立的真实村庄环境 | 村庄初始化流程是否仍需过多人工处理 |
| 课程任务 | 课程阶段、任务说明、完成状态、小组加入和任务入口 | 让学生知道当前阶段要做什么，避免平台只是工具集合 | 任务是否足够清楚，学生是否会按流程进入相应功能 |
| 个人工作底图 | 个人空间、AOI范围、遥感影像、OSM、DEM、等高线和建筑等数据处理，个人图层版本 | 让学生体验规划工作底图的生产和修订过程 | 处理时间、失败恢复和学生对数据来源的理解程度 |
| 共享调查与现状校核 | 建筑等对象的增删改、调查状态、照片、问题信息、评论和共同校核 | 汇集不同学生的调查结果，形成班级共享现状 | 评论、问题和访谈信息的使用频率可能较低，需要实证判断 |
| 共享基线与小组方案 | 管理员冻结现状版本，小组从共同基线建立方案，支持基线更新、组内覆盖和冲突提示 | 保证各组使用同一现状起点，同时保留不同方案 | 冻结、更新和冲突处理是否容易被学生理解 |
| 二维与三维表达 | 2D地图与Cesium三维村庄切换，围绕同一小组空间开展设计 | 二维用于精确编辑和关系判断，三维用于体量、界面和尺度体验 | 二三维数据一致性、性能和学生切换使用方式 |
| 建筑更新 | 建筑照片处理、立面生成流程、建筑模型生成与替换、小组模型素材 | 支持单体建筑层面的更新体验，并展示AI和三维技术的交叉 | 生成结果仍需人工判断，不能直接视为合理设计 |
| 公共空间场景工作室 | 在三维中划定范围、放置和移动树木、座椅、花坛等组件，以同一场景文档进行2D校核，并支持保存和恢复 | 让学生直接进行场所设计，增强空间操作和即时反馈 | 需要通过真实任务检验其易用性、吸引力和规划意义 |
| 过程记录 | 课程任务日志、对象修改记录、个人图层版本、小组方案版本和相关操作数据 | 为形成性评价提供过程材料，不只观察最终图纸 | 日志字段是否足以回答论文问题，哪些行为具有分析意义 |

从功能结构看，平台已经不只是地图展示网页，而是初步形成了三个设计尺度：微观的建筑更新、中观的公共空间场景设计，以及尚待建设的宏观村庄营造。不过，现阶段最成熟的核心仍是课程任务、个人底图、共享现状、小组方案、二维三维表达和版本化协作。

## 四 未来可以增加的功能与模块

未来完善不宜同时追求大量新功能，可以按论文和课堂需要分为三个层次。

### 近期优先完善

1. **把现有功能任务化。**围绕真实村庄设置“改善村口交往空间”“修复滨水步行联系”“为空置建筑配置新用途”等短任务，为学生提供背景、服务对象、约束和成果要求，但不设置唯一答案。
2. **补强平台引导。**增加简短的新手流程、阶段提示、示例成果和失败恢复，减少学生因不熟悉界面而放弃使用。
3. **完善关键日志。**重点记录学生是否进入任务、使用哪些工具、是否切换二维三维、是否创建和修改方案版本，而不是无差别收集大量点击。
4. **加强“调研—判断—方案”的可选关联。**允许学生把照片、问题或调查发现引用到诊断和方案说明中，但不强迫每次设计操作都填写复杂证据链，以免增加课堂负担。
5. **增加方案比较。**让学生直观看到现状、初步方案和修改方案之间的变化，并比较不同小组的空间选择及理由。

### 中期建设村庄营造实验室

可以在三维模块中加入类似《江南百景图》的轻量化村庄营造模块，但借鉴的是俯视建造、资源配置和即时反馈的交互逻辑，不复制商业游戏的美术或玩法。学生可以在有限的土地、资金和公共资源条件下布置道路、建筑、公共服务和产业设施，系统反馈可达性、服务覆盖、空间冲突、建设成本、生态影响等变化。

该模块不应把规划简化为追求最高分。更合适的方式是让不同小组保存不同发展路径，比较其在居住改善、产业发展、公共服务、生态保护和文化传承之间的取舍，并要求学生说明指标未能覆盖的现实问题。游戏化的核心是“情境—任务—操作—反馈—反思”，而不是积分、排行榜和装饰动画。

### 后期探索AI情境模块

AI可以根据真实村庄资料生成可编辑的任务文本、角色说明、资源变化和突发情境，例如人口变化、旅游压力、极端天气或预算调整；也可以帮助整理方案差异、提出需要核实的问题，或以明确标注的虚拟角色提供不同立场的反馈。但AI不能冒充真实村民，不能生成未经核实的“地方知识”，也不应直接判定哪个规划方案最好。

此外，还可以建设面向教师和管理员的课程观察面板，汇总任务进度、功能使用、版本变化和常见困难。不过，这一模块应服务教学观察，而不是对学生进行简单排名。

## 五 论文的大致方向

论文暂时可以定位为：**生成式AI辅助的乡村规划互动学习环境构建与课堂应用研究。**“规划教育转型”是研究背景，“乡村规划实践教学”是应用场景，“规划领域人员与大模型共同开发平台”是新的研究切入点，“学生参与、沉浸体验和实践应用”是需要通过课堂材料检验的应用层问题。

核心科学问题可以暂时表述为：

> 本研究面向生成式人工智能推动规划教育转型的背景，探索规划领域非专业开发者借助大模型将教学设想持续转译为可运行、可验证和可迭代的互动式学习环境的实现机制，并以乡村规划实践课程为应用场景，分析该环境如何通过真实村庄、二维三维表达、协作任务和场景化设计连接课堂认知、现场调查与方案创造，以及其在学生参与、沉浸体验和实践应用中的使用表现与边界。

论文可以采用“双层主线”：

1. **人机协同开发层。**分析教学设想如何经过需求表达、任务分解、大模型协作、代码实现、人工检查、测试和迭代形成平台；重点不是证明AI会写代码，而是说明代码门槛下降后，需求表达、系统整合、结果验证和专业判断如何成为新的关键能力。
2. **课堂应用层。**分析平台如何组织真实村庄、个人底图、共享现状、小组方案、二维三维和场景任务；重点观察学生实际使用了什么、哪些内容更能吸引其参与、沉浸感如何表现，以及哪些功能没有进入真实课程过程。

可能的创新不宜写成“开发了很多新功能”，而可以集中在三点：第一，把研究对象从学生使用单项AI工具推进到规划领域人员借助大模型构建专用学习环境；第二，形成“人机协同开发—课堂应用—使用反馈—继续迭代”的双层循环；第三，把真实村庄、二维三维和微观—中观—宏观的空间创造组织成一个可在课堂中检验的互动学习环境。

研究材料可以包括两类。开发层使用需求对话、设计规格、实施计划、代码提交、测试、错误和迭代记录；课堂层使用平台日志、方案版本、学生成果、课堂观察、学生访谈和简短问卷。课程约有17名学生，不适合进行大样本因果推断，也不宜在没有前后测和对照组的情况下宣称平台显著提高学习成绩。更合适的定位是设计研究和形成性评价，通过描述性统计、主题分析和典型案例追踪，判断平台与课程是否适配、学生如何使用、哪些作用可以被观察、哪些障碍仍然存在。

## 六 希望继续讨论的问题

后续可以围绕以下问题继续推敲，而不必默认当前方向已经完全确定：

1. 论文应把“AI辅助规划专业人员开发平台”放在主创新位置，还是把它作为平台形成条件，把“沉浸式乡村规划学习环境”作为主线？
2. 双层主线是否会使一篇期刊论文范围过大？是否应在开发机制和课堂应用之间选择一个主问题，另一个作为支撑？
3. “参与”和“沉浸”应该如何转化为可观察指标，才能避免只依靠满意度问卷？
4. 现有公共空间场景工作室能否承担课堂实证，还是必须完成宏观村庄营造模块后论文才有足够辨识度？
5. 类《江南百景图》模块应模拟哪些规划变量，如何避免规则过度简化、唯一评分和娱乐化掩盖专业学习？
6. 17名学生的日志、成果和访谈怎样组合，才能形成可信但不过度外推的证据？
7. 如果以《南方建筑》为目标期刊，论文需要把重点放在教学实验、数字平台设计、人机协同开发，还是三者之间的某种明确关系上？
8. 论文标题、科学问题和章节结构如何进一步收缩，使创新集中且与现有平台、可取得的数据相匹配？

在后续讨论中，应允许对上述设想提出反对意见。尤其需要警惕三种倾向：把尚未课堂验证的功能写成教学成效；为了追求新颖而夸大AI的作用；为了强调游戏化而忽略乡村规划问题本身的复杂性。
