> **过程文档**
>
> 本文记录平台代码、界面与功能的迭代过程，便于回顾“为什么修改、修改了什么、如何验证”。  
> 它与平台运行时采集的学生操作日志是两套独立记录：本文面向项目开发，学生操作日志面向教学研究与后台分析。

## 记录规则

- 每次形成一个可说明的功能调整后新增一条记录，不必逐行记录代码。
- 每条记录包含：目标、主要修改、影响范围、验证结果和后续事项。
- 尚未完成或尚未验证的内容要明确标注，不把设计设想写成已完成功能。
- Git 提交用于保存代码快照；本日志用于说明每个快照背后的产品与教学逻辑。

## 2026-07-21｜Supabase Auth 自由注册与可信角色权限

**状态：前端认证改造、数据库迁移、管理员删除用户函数及远程权限校验已完成；当前改动尚未提交 Git。**

### 迭代目标

用 Supabase Auth 替代浏览器本地身份和公开账户表，在保留“姓名 + 学号 + 密码”使用习惯的同时，让每名学生拥有独立、可验证的账号，并让管理员／教师权限只由数据库决定。

### 主要修改

- 登录与注册界面继续只要求姓名、学号和密码，不向学生暴露邮箱概念；系统在内部把规范化学号映射为项目专用的隐藏邮箱，再调用 Supabase `signUp` 和 `signInWithPassword`。
- 注册保持自由开放；Supabase 的“确认邮箱”已由项目负责人关闭，学生注册后无需收取隐藏邮箱的验证邮件即可进入平台。
- 新增 `profiles` 资料表并与 `auth.users` 一一关联；学号全局唯一，新注册账号一律由数据库触发器赋予 `student` 角色，客户端提交的角色字段不会生效。
- 管理员、教师和普通学生的判断统一读取 `profiles.role`，删除原先根据“管理员”姓名或学号 `332` 在浏览器中推断管理员身份的逻辑。
- 首页、主平台和管理员页面共用同一个 Supabase 客户端与 Auth 会话；本地存储只保留兼容缓存，不再作为可信登录来源，旧版本地身份会在升级后失效一次。
- 为认证模型、权限模块、认证界面和主应用脚本增加统一发布版本号，避免浏览器继续复用没有密码输入框的旧登录脚本。
- 管理员用户列表改为读取 `profiles`；删除账号通过受保护的 `admin-delete-user` Edge Function 完成，由函数再次验证调用者是否为管理员，浏览器不再直接操作公开账户表。
- 编辑锁、心跳、释放锁和批量保存 RPC 改为从 `auth.uid()` 获取真实操作者，并把 Auth UUID 写入锁、批次和版本历史；前端传入的姓名只作兼容参数，不能冒充其他学生。
- 收回匿名角色对资料表、旧 `auth_users`／`user_sessions` 表和关键编辑 RPC 的权限；登录用户只可修改自己的普通资料字段，不能自行提升角色。
- 新增可重复执行的迁移脚本 `supabase_SQL/Supabase Auth Profiles and Identity RLS.sql`，并已在远程 Supabase 项目执行；部署了启用 JWT 校验的 `admin-delete-user` Edge Function。

### 影响范围

- 首页、互动平台与管理员页面的注册、登录、会话恢复和退出登录。
- 管理员／教师／学生角色判断及管理员删除账号流程。
- 现状要素编辑锁、保存历史与操作归属。
- Supabase Auth、`profiles`、旧身份表权限和相关 RPC。

### 验证结果

- `features` 下 103 项平台自动化测试全部通过；首页地图 7 项测试全部通过，共 110 项，其中包含认证脚本缓存失效回归测试。
- `auth-system.js`、`admin.js`、`app.js`、认证模型和访问控制模块的 JavaScript 语法检查全部通过。
- 首页 TypeScript 编译通过；现有 Vite 生产构建仍被 `kimi-plugin-inspect-react` 缺少 `@babel/plugin-proposal-decorators` 阻断，该依赖问题早于本次认证改造且本轮未擅自修改依赖清单。
- 远程数据库确认 `profiles` 已启用 RLS：匿名角色不能读取资料；匿名角色不能调用要素锁定和批量保存 RPC，`authenticated` 角色可以调用。
- 远程迁移 `supabase_auth_profiles_and_identity_rls`、`retire_legacy_public_auth_policies` 均已存在；`admin-delete-user` Edge Function 为 `ACTIVE` 且启用 JWT 校验。
- 首个正式账号已完成注册：姓名“管理员”、学号 `332`；经身份核对后，其 `profiles.role` 已由默认的 `student` 提升为 `admin`，未创建临时测试账号。

### 后续事项

- 管理员账号已完成注册和数据库角色提升；浏览器刷新或重新登录后会按 `profiles.role = admin` 获得管理权限。
- 其他学生可直接自由注册，数据库会自动赋予 `student` 角色。
- Supabase 安全顾问仍报告若干本次认证范围外的旧表宽松策略和两个未启用 RLS 的 MC 同步表，建议后续单独安排一次全库权限收紧，不与本轮登录改造混在一起。

## 2026-07-20｜共享现状校核的显式保存、对象锁与版本基线

**状态：前端代码、数据库迁移、Realtime 配置与自动化验证已完成；当前改动尚未提交 Git。**

### 迭代目标

把“系统｜现状空间”明确为全班共同校核的工作版本：学生可以编辑不同要素并集中保存，同时保留教师提供的初始现状 V0、每批修改历史和后续正式校核版本。

### 主要修改

- 空间工具增加常驻的“保存编辑”和“放弃修改”操作；新增、删除、编辑顶点、移动和旋转先形成当前用户的本地草稿，点击保存后才成批写入数据库。
- 保存前自动生成修改摘要，例如“修改建筑 2 个、新增道路 1 条”，并允许补充不超过 200 字的调研依据或修改说明。
- 新增要素级编辑锁：锁定范围为“空间 + 图层 + 要素编号”，不同学生可以同时编辑不同对象，但不能同时修改同一对象。
- 编辑锁采用 90 秒租约和 30 秒心跳；放弃修改、保存成功或租约失效后释放，异常离开时也会自动过期，避免永久占用。
- Supabase 已执行共享现状版本与对象锁迁移，并将相关表加入 Realtime；浏览器角色只能读取锁、历史与快照，不能直接写表，编辑必须经过锁和批量保存 RPC。
- “冻结版本”和“创建永久 V0”仅向可信后台 `service_role` 开放，当前网页匿名角色不能调用；待接入 Supabase Auth 后再开放教师角色。
- 数据库保存函数再次校验修改者是否持有有效对象锁，冲突控制不只依赖前端按钮。
- 每次成功保存建立修改批次和逐要素版本记录，保存人、时间、摘要、备注以及修改前后几何和属性均可追溯。
- Realtime 继续监听共享现状图层；其他同学保存后通常约 1 秒触发刷新。当前用户存在未保存草稿时不会被远程刷新覆盖，而是提示先保存或放弃；右下角刷新按钮仍可手动同步。
- “系统｜现状空间”继续作为全班共享可编辑的校核版本；初始 V0 不放入普通空间下拉框，而是隐藏在“图层与项目设置—版本管理”中。V0 对比始终读取教师提供的完整静态矢量，不会因 Supabase 只保存覆盖项而遗漏未修改要素。
- 管理员及预留的教师角色可以把当前校核结果冻结为正式版本；冻结前会合并完整原始矢量、数据库覆盖项和删除记录，避免正式版本只保存改动过的对象。普通学生只能保存校核修改和查看已有版本记录。
- 新增可重复执行的数据库脚本 `supabase_SQL/Shared Current Survey Versioning and Feature Locks.sql`，并把相关表加入 Realtime publication 配置。

### 影响范围

- 2D 空间工具及几何编辑流程。
- Supabase 规划要素保存、并发锁、修改历史与版本快照。
- 图层与项目设置抽屉中的版本管理模块。
- 2D/3D 数据刷新与本地草稿保护。

### 验证结果

- `app.js` 及本次涉及的 5 个前端模块 JavaScript 语法检查全部通过。
- `features` 下共 86 项自动化测试全部通过，其中包含显式保存、对象级锁、V0 隐藏入口和数据库锁校验回归测试。
- `git diff --check` 未发现空白字符错误；仅存在仓库既有的 LF/CRLF 换行提示。

### 待执行事项

- 在 Supabase 项目的 SQL Editor 中执行 `Shared Current Survey Versioning and Feature Locks.sql`。首次执行会建立永久只读 V0 版本记录；实际 V0 图形读取仓库中的教师原始静态矢量，正式冻结版本则保存完整合并结果。
- 随后重新执行 `Realtime Publication Setup.sql`，使版本与锁表加入实时发布。
- 浏览器控制组件本轮无法可靠识别 Edge 当前标签页地址，已按安全策略停止自动点击，未对远程数据库做未经验证的操作。

## 2026-07-20｜工作区响应式顶栏与协作抽屉整理

**状态：代码调整与自动化验证已完成；当前改动尚未提交 Git，由项目负责人验收后决定是否存档。**

### 迭代目标

解决左右侧栏展开后顶部工作区控件拥挤、项目设置抽屉过宽，以及班级留言缺少视觉层级的问题；同时明确“问题标记”和“班级讨论”是两种不同操作。

### 主要修改

- 顶部情境栏改为“侧栏状态 + 中央容器宽度”的混合响应式布局：左栏展开时隐藏重复课程摘要，右栏单独展开时保留紧凑摘要，左右栏均开时固定使用图标操作，左右栏均关时显示完整文字。
- 顶栏进一步改为六槽位空间预算网格：除空间选择器外，其余操作按内容宽度占位；选择器接收全部真实剩余空间，不再使用固定最大宽度或自动外边距制造留白。
- 左栏展开时同步移除重复的课程摘要列；中央区域变窄时先收起“图层与项目设置”文字，再收起“班级讨论”文字，并在右端保留 14px 安全内边距，避免设置按钮越界。
- 将“返回首页”按钮从左侧课程标题移入顶部工作区最左端，作为固定 36px 图标槽位；继续复用原有返回逻辑，且不再在左侧重复显示。
- 顶部保留“班级讨论”，将“标记问题”移入“图层与项目设置”抽屉，避免主工作区操作过密。
- 设置抽屉宽度收窄为约 320px，内容顺序调整为“图层控制—空间工具—问题与留言—导出”。
- 抽屉操作区仅保留“标记问题”按钮；班级讨论直接放在下方讨论模块中，不再重复设置跳转按钮。
- 空间选择器改为流式宽度，会占用顶栏的剩余空间，并在左右侧栏展开时自动收缩。
- 班级讨论标题下新增留言输入框与“发表留言”按钮；顶部“班级讨论”快捷入口会打开抽屉并聚焦输入框。
- 重新设计班级留言的显示层级：作者与时间分列，正文采用 14px / 1.55 行高，点赞、回复、定位使用紧凑按钮，回复内容使用嵌套浅色区域呈现。
- 没有回复时不再渲染可见的空回复背景；点击回复或已有回复时才显示该区域。
- 同步调整空间管理、协作入口与响应式布局相关回归测试，不改变首页、地图数据及 Supabase 表结构。

### 验证结果

- `app.js` JavaScript 语法检查通过。
- 工作区、课程流程、空间管理、对象协作、首页地图等共 84 项自动化测试全部通过。
- `git diff --check` 未发现空白字符错误；仅存在仓库原有的 LF/CRLF 换行提示。

## 2026-07-17｜任务—情境一体化工作区（第一阶段）

**状态：代码调整已完成，待本次完整任务验收后由项目负责人决定是否提交 Git 存档**

### 迭代目标

在保留原有地图平台能力的前提下，解决“课程任务栏只是额外增加的一列”、2D/3D 与课程流程割裂、全局信息挤占对象信息区等问题。课程阶段用于提示当前情境和推荐操作，不作为限制学生探索平台的强制门禁。

### 主要修改

- 将课程结构整理为“2 个准备阶段 + 4 个实践阶段”：加入小组、学习准备、调研采集与现状校核、现状诊断与课堂汇报、方案设计与迭代、成果整理与提交。
- 最左侧保留可收缩的课程阶段栏；展开后优先展示当前阶段的成果、资料和建议操作，不再重复生成独立平台入口页。
- 地图上方增加稳定的情境栏，显示当前村庄、课程阶段、空间及小组信息；切换阶段只改变推荐关注点，不关闭其他已有功能。
- 取消“共建模式 / 规划模式”抽象切换，保留 2D / 3D 作为同一工作区的数据视图切换。
- 2D 与 3D 共用当前空间和对象上下文，切换视图时不再主动清除已选择的对象。
- 右侧固定为“对象信息与协作”，用于属性、照片和对象相关讨论；未选择对象时显示清晰的操作提示。
- 将全局图层、班级问题与留言、空间工具等集中到“图层与项目设置”抽屉，避免占用对象信息区。
- 问题标记与建筑、道路等普通矢量要素可同时浏览和交互；问题标记保持独立的点状入口，对象留言继续依附于选中要素。
- 修复首页内嵌页面尚未完成构建时绑定事件导致的初始化异常。

### 影响范围

- 课程阶段模型与最左侧任务栏。
- 平台主布局、顶部情境栏和项目设置抽屉。
- 2D/3D 视图切换与对象选择状态。
- 普通矢量要素、问题标记、班级留言和对象讨论的入口组织。

### 验证结果

- 新增课程情境、统一工作区交互和首页初始化时序的自动化测试。
- 已通过 Edge 本地页面结构与视觉复核：首页保持原有内容结构，平台可显示六阶段栏、情境栏、对象信息区及项目设置抽屉。
- 本条记录只描述项目代码迭代，不替代后台记录学生操作行为的运行时日志。

### 本阶段暂不处理

- 不修改 Supabase 数据表和现有云端数据。
- 不在本阶段实现教师后台、成果冻结提交及完整版本管理界面。
- 不把过程中的每个实施检查点单独作为 Git 备份；完整任务完成后再决定是否提交存档。

## 2026-07-15｜任务驱动课程工作台第一阶段
